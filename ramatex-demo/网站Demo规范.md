# 网站 Demo 规范

本规范适用于 `ramatex-demo`，也可作为后续独立站 demo 的通用基线。

本文件是通用规范；当 `设计方案.md` 已明确项目结构时，以 `设计方案.md` 为准。Ramatex 当前版本已经明确为：公开首页四模块、品牌空间四模块、单款详情和定制器核心功能页。

Ramatex 当前版本保持纯静态，不引入 React 或 Ant Design；如需要 Ant Design，必须另行迁移为 React 工程。纯静态版本应使用 CSS token 对齐 `DESIGN.md` 的视觉规范。

## 1. Demo 类型判断

独立站 demo 的目标是让访客相信这个品牌、产品或服务真实存在，并愿意继续了解或联系。

它不同于：

- 管理后台 demo：强调工作流和信息效率
- 工具 demo：强调交互能力和结果生成
- 营销活动页：强调单次转化和短期促销

独立站 demo 应优先完成：

```text
定位清楚
信任成立
内容可替换
转化路径明确
```

## 2. 文件与目录规范

第一版推荐：

```text
index.html
brand-space.html
styles.css
app.js
产品方案.md
视觉规范.md
网站Demo规范.md
assets/
references/
```

规则：

- 页面少于 3 个时，优先单 HTML 或少量静态 HTML。
- 不为简单静态站引入框架。
- 业务数据可先放在 `app.js` 或后续独立 `data.js`。
- 图片统一放入 `assets/` 下按用途分组。
- 参考资料放入 `references/`，不要混在页面素材里。

## 3. 页面结构规范

通用独立站页面通常应覆盖：

- 导航
- 首屏
- 业务能力或产品
- 优势 / 信任背书
- 案例 / 场景
- 合作流程
- 联系 / 合作
- 页脚

Ramatex 当前版本的项目级覆盖规则：

- 公开首页只保留 Banner、款式、视频、面料、Footer。
- 品牌空间只保留项目 Banner、款式、视频、面料、Footer。
- 公开站顶部不放中间栏目导航，只保留 Logo、语言切换和品牌空间入口。
- 品牌空间从公开站右上角新开页进入。
- 品牌空间入口页使用访问凭证卡片，凭证可为空或任意输入，不做真实校验。
- 品牌空间入口页不展示 Ramatex 相关字样，不出现账号、密码、验证码、忘记密码。
- 品牌空间顶部不放公开站或返回官网按钮。
- 单款详情和定制器保留为核心功能页。
- 底部使用常规网站 Footer，不放大号获取报价 / 客户登录 / 品牌空间 CTA。

页面顺序应服务访客决策。通用顺序可以是：

```text
我是谁
我能帮你什么
为什么可信
有哪些结果
下一步怎么做
```

Ramatex 当前版本的顺序更偏服装展示和选款：

```text
先看到视觉 Banner
再看款式
再看视频
再看面料
最后进入常规 Footer
```

## 4. 首屏规范

首屏不是说明书，也不是后台入口。Ramatex 当前版本首屏应作为服装官网广告坑位处理。

必须有：

- 清晰品牌识别
- 服装、上身、运动、系列或面料相关图片
- 短 campaign 字样
- 极简轮播控制器

避免：

- 只有抽象渐变或装饰图
- 大标题只写愿景口号
- 大段功能说明
- 页面外层按钮组
- 卡片式 slide 信息条
- 使用看不出行业的通用模板图

## 5. 导航规范

导航用于快速理解网站内容，而不是堆满栏目。

第一版建议：

```text
Home
Capabilities
Products / Solutions
Cases
About
Contact
```

规则：

- 顶部导航项不超过 6 个。
- CTA 可独立放右侧，如 `Get a Quote` 或 `Contact Us`。
- 移动端导航需要可点击、可关闭、可回到当前页面。
- 页面锚点和导航命名保持一致。
- Ramatex 公开站不使用中间栏目导航；品牌空间入口放右侧，命名为 `品牌空间 / Brand Space`，不叫 `客户登录`。

## 6. 内容与文案规范

页面可见文案应像真实网站，不像开发说明。

禁止出现：

```text
demo
mock
placeholder
local image
test
lorem ipsum
点击这里测试
这里放图片
模块
链路
这个区域用于
先进入详情页
客户登录
```

文案要求：

- 每段说明尽量不超过 3 行。
- 标题具体，不只写 abstract nouns。
- CTA 使用具体动作，例如 `Request a Quote`、`Talk to Sales`。
- 不写未经确认的认证、客户、销量、产能数字。
- 如资料未确认，用中性表达，为后续替换留位置。
- Ramatex 页面文案应模拟真实服装网站，多使用款式、面料、动态预览、样衣、MOQ、交期、定制范围等业务词。
- 面向品牌方的专属入口统一称为 `品牌空间`。

## 7. 视觉规范

独立站需要形成品牌感，但不能牺牲信息清晰度。

基本要求：

- 字号层级稳定。
- 页面宽度、间距、栅格统一。
- 卡片只用于重复条目、表单或需要框定的信息块。
- 不把每个 section 都做成浮动卡片。
- 首页和品牌空间的 Banner 下方统一使用浅 `surface` 背景，款式和面料使用独立图片陈列卡，视频播放器使用独立容器承载。
- Banner 自动 4 秒轮播，分页器保留 4 个短白条；当前分页短条内部显示 4 秒填充进度。
- 区块之间主要靠背景层级、容器和间距区分，不依赖粗重横线或渐变背景。
- 款式、视频、面料模块之间的主要视觉间距控制在约 `60px`。
- 款式和面料卡片必须是独立卡片，不用一个大白色容器把所有卡片连接在一起。
- Ramatex 款式卡片只保留图片和款名，桌面 4 列、手机 2 列。
- Ramatex 视频切换卡只保留 poster 和播放符号，不放视频名。
- 视频模块暂不提供更多列表入口；右侧缩略图必须和主播放器内容一一对应，并有清晰选中态。
- Ramatex 面料卡片只保留图片和面料名，桌面 4 列、手机 2 列。
- Ramatex 款式和面料 hover 只显示名称遮罩，不显示图标、价格、箭头或数据。
- 单款详情页只保留 `开始定制` 作为主动作，不出现询盘、报价、购物车或立即购买。
- 单款详情右侧不做颜色、数量、面料选择，不固定展示某个面料；只放 `参考价`、`可选尺码`、`可定制内容` 这类上下结构短信息，完整尺码表放到下方详情。
- 单款详情返回入口统一显示 `返回`；根据来源回首页、品牌首页或更多列表。PDP 顶部主体作为一个整体随页面滚动，缩略图、大图和右侧信息不要各自 sticky。
- 面料卡片必须进入面料详情页；面料详情图片切换方式和款式详情保持一致，只展示面料编号、基础属性和纯色块可选颜色，不出现 `开始定制`、`加入选品篮`、数量或规格选择。
- 定制页是一屏工作台：左/中为 3D 区域，右侧为唯一配置区，宽度使用动态范围；最右侧竖向 rail 为 `面料 / 图案`，rail 和内容区应呈现一体化面板感，选中 tab 与面板同色，未选中 tab 使用浅灰底。面料使用多个应用区域抽屉，每个抽屉内选择面料和颜色；单个部位面料较多时使用抽屉内分页，每页 9 个，分页只显示 `当前页 / 总页数`，面料卡默认只显示图片，hover 使用和首页一致的深色渐变遮罩显示名称和基础信息；颜色用一行较大的方形纯色块，颜色过多时按一行分页。图案通过 `新增图案` 创建对象，对象内用 2x2 来源卡片选择图案库、上传图片、输入文字或 AI 生成；输入文字支持字体 select、预设色块和 Coloris 色盘；图案库每页 9 个且只显示图片不显示命名，分页只显示 `当前页 / 总页数`，AI 默认不显示结果，点击生成后桌面 4 个一行、小屏 2 个一行。工艺用图示样片卡片选择，可添加多个图案，不做区域概念。右侧不放独立方案摘要，底部只保留 `加入选品篮`。
- 公开站点击开始定制需要进入品牌空间访问凭证页；品牌空间内定制后加入选品篮，再统一提交订单并进入订单中心。
- B2B 链路统一使用 `选品篮`，不使用 `购物车` 文案。
- 不使用大面积单一色系导致页面疲劳。
- 不用过度科技感渐变，除非品牌确实需要。
- 按钮、标签、输入框状态完整。

## 8. 图片与素材规范

独立站必须使用与业务直接相关的视觉资产。

素材优先级：

1. 真实品牌、产品、工厂、团队、案例图片
2. 可明确代表产品或行业的授权图片
3. AI 生成的高质量业务图
4. 简单占位图

占位图只允许在内部开发阶段使用，不应出现在最终 demo 演示中。

图片应提前确定：

- 用途
- 推荐比例
- 文件命名
- 来源
- 是否可对外展示

## 9. 响应式规范

至少检查：

- 390px 宽移动端
- 768px 平板
- 1440px 桌面端

要求：

- 首屏文字不遮挡图片主体。
- 导航在移动端不溢出。
- 按钮文字不换成难看的多行。
- 图片比例稳定，不因加载或 hover 导致布局跳动。
- 表单字段在手机上单列显示。

## 10. 交互规范

静态独立站也需要基础交互完成真实感。

建议实现：

- 移动端菜单开关
- 平滑锚点滚动
- FAQ 或能力项展开
- 表单基础校验
- 提交后的前端状态反馈

避免：

- 无意义动画
- 自动轮播导致访客无法阅读
- CTA 点击没有任何反馈
- 表单声称已真实提交但没有后端

## 11. 可维护性规范

后续实现时应做到：

- CSS 变量集中定义颜色、字体、间距。
- 重复数据尽量结构化，便于改文案。
- 每个 section 有清晰 class 命名。
- 图片路径集中管理或按模块就近写清楚。
- 不把大量内联样式写在 HTML 标签上。

## 12. 验收清单

交付前检查：

- 页面可见文案没有 demo/mock/placeholder/test。
- 首屏以图片和短 campaign 字样表达品牌与业务。
- Ramatex 首屏不强制放 CTA，整张 Banner 可点击。
- 所有图片都能加载。
- 桌面和移动端没有明显重叠、溢出和跳动。
- 表单状态完整。
- 页面结构能支持后续替换真实资料。
- Ramatex 首页和品牌空间没有额外的项目支持第 5 模块。
- Ramatex 底部是常规 Footer，不是大号转化区。
- Ramatex 视频区使用本地 mp4 在页面内播放或切换，不以弹窗作为首页视频区主交互；只有主区域播放视频，缩略入口只展示对应视频截帧封面和播放符号。视频列表页可点击单条封面播放该视频。
- Ramatex 内容区使用浅 `surface` 背景 + 独立图片陈列卡，不使用渐变、粗横线或外层大白盒区分款式、视频、面料。
