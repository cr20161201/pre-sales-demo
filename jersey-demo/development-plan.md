# 球服定制网站 DEMO 开发计划

## 1. 项目目标

做一个简单但完整可演示的球服定制网站 DEMO，聚焦从选款、查看详情、进入伪 3D 定制到团队批量下单的核心链路。

产品分两种流程：

- 成品球衣：已有固定款式和颜色，只能在指定位置加图案、加文字、加号码，且支持多个位置选择。
- 白板球衣：从空白底板开始，可以选择面料、花纹和配色；确定基础设计后，再进入同样的加图案、加文字、加号码和团定下单流程。

本阶段只做核心页面与前端交互闭环，不接真实支付、真实库存和用户系统。管理端只做 DEMO 页面和本地模拟数据，不接真实后台接口。

## 2. 核心页面

### 2.1 球服列表页

目标：让用户快速浏览球服款式，并进入详情或直接定制。

核心内容：

- 顶部导航：品牌名、球服列表、我的设计、购物车/下单入口。
- 筛选项：运动类型、版型、颜色、价格区间。
- 产品类型筛选：成品球衣、白板球衣。
- 排序项：推荐、价格、最新。
- 球服卡片：封面图、名称、产品类型、适用运动、基础价格、可定制标签。
- 操作按钮：查看详情、开始设计。

验收标准：

- 至少展示 6 个球服款式。
- 支持基础筛选和排序。
- 点击球服卡片可以进入详情页。
- 点击开始设计可以进入 3D 球服设计页。

### 2.2 球服详情页

目标：展示单个球服的卖点、基础信息和可定制项，引导用户开始设计。

核心内容：

- 球服大图/多图预览。
- 名称、价格、适用运动、材质、尺码说明。
- 款式说明：领口、袖型、版型、面料特点。
- 可定制范围：
  - 成品球衣：指定位置加图案、加文字、加号码，不开放整体面料、花纹和配色。
  - 白板球衣：选择面料、花纹、主色、副色、领口颜色、袖口颜色，再配置图案、文字和号码。
  - 实际队员姓名和号码在下单页批量录入。
- 尺码说明：S、M、L、XL、XXL，具体尺码在团定下单页按队员录入。
- 操作按钮：加入方案、开始 3D 定制。

验收标准：

- 能根据列表页传入的球服 ID 展示对应详情。
- 能展示当前商品是成品球衣还是白板球衣。
- 能查看当前商品的可定制边界和尺码说明。
- 点击开始 3D 定制时保留当前球服和基础配置。

### 2.3 3D 球服设计页

目标：提供 DEMO 的核心亮点，让用户看到一个“像 3D 定制器”的球服设计页面。该页面只做样子货效果，不需要真实 3D 模型、不需要真实旋转交互，也不需要生产级贴图能力。

核心内容：

- 球服预览区：用伪 3D 球服图、CSS 立体效果或正反面图片模拟 3D 观感。
- 视角切换：正面、背面、侧面，用切换图片/布局状态实现即可。
- 流程模式：
  - 成品球衣模式：展示固定球衣底图，只开放指定位置的加图案、加文字、加号码。
  - 白板球衣模式：先选择面料、花纹和配色，再开放同样的加图案、加文字、加号码。
- 设计控制面板：
  - 白板基础设计：面料、花纹、主色、副色、领口颜色、袖口颜色。
  - 加印设计：选择加印位置、加印类型、图案、文字、号码。
  - 多位置配置：左胸、右胸、胸前中部、背部上方、背部中部、袖口、肩部等。
  - 文字内容：客户手动输入文字，不做内置文字模板。
  - 号码内容：客户手动输入号码，不做内置号码模板。
  - 图案内容：队徽、赞助商图案、装饰图案。
- 实时价格：基础价格 + 定制项加价。
- 操作按钮：重置设计、保存设计、下一步下单。

伪 3D 实现建议：

- 不接入 Three.js / React Three Fiber，避免把时间花在真实 3D 能力上。
- 使用 HTML + CSS + 图片叠层实现球服预览。
- 球服本体可以用 PNG、SVG、CSS shape 或占位图模拟。
- 成品球衣用固定底图，颜色和花纹不可改，只叠加指定位置的文字、号码、图案。
- 白板球衣的颜色变化通过 CSS 变量、滤镜或覆盖层实现。
- 白板球衣的花纹变化通过不同背景图、渐变、条纹背景或覆盖层实现。
- 客户手动输入的文字和号码用绝对定位叠加在球服正面/背面。
- 面料选择只改变材质标签、局部纹理背景或高光效果，不需要真实材质渲染。
- 多位置加印用配置数组驱动，每个位置对应一个固定坐标和展示区域。

验收标准：

- 页面视觉上像一个 3D 球服定制器。
- 可以切换正面、背面、侧面预览。
- 成品球衣只能修改指定位置上的图案、手动输入文字和手动输入号码。
- 白板球衣可以修改面料、花纹、颜色，再修改指定位置上的图案、手动输入文字和手动输入号码。
- 多个加印位置可以同时存在，预览区能显示对应变化。
- 当前设计配置可以进入下单页。
- 页面在桌面端可正常使用，移动端至少布局不破。

### 2.4 下单页

目标：让用户以团定方式确认同款球服的批量订单。核心是同一款式、同一设计方案下，可以录入多个队员的尺码、姓名、号码和数量。

核心内容：

- 订单摘要：球服款式、统一设计配置、预览图。
- 团队名单表格：
  - 队员姓名。
  - 球衣号码。
  - 尺码。
  - 数量。
  - 单行小计。
- 表格操作：新增队员、删除队员、复制上一行、批量生成号码。
- 价格明细：单件基础价、统一定制费用、总件数、订单总价。
- 收货信息表单：联系人、手机号、地址、备注。
- 生产说明：预计制作周期、不可退换提示。
- 操作按钮：返回修改、提交订单。
- 提交成功状态：订单号、订单摘要、返回列表。

验收标准：

- 能展示从 3D 设计页带来的配置。
- 能录入多名队员的姓名、号码、尺码和数量。
- 能按队员明细统计总件数和总价。
- 表单有基础校验。
- 提交后显示模拟订单成功页或成功弹窗。

### 2.5 管理端页面

管理端目标：让 DEMO 不只是前台能演示，还能展示“可配置范围从哪里来”“不同客户看到哪些专属产品”“订单如何转成生产信息”。

#### 2.5.1 球衣可定制范围配置页

目标：配置每款球衣实际允许客户修改和加印的范围。

核心内容：

- 球衣选择：选择要配置的成品球衣或白板球衣。
- 产品类型标识：成品球衣、白板球衣。
- 成品球衣配置：
  - 固定底图、固定颜色、固定花纹。
  - 可加印位置：左胸、右胸、胸前中部、背部上方、背部中部、袖口、肩部等。
  - 每个位置允许的内容类型：图案、文字、号码。
  - 每个位置的建议尺寸、价格、备注。
- 白板球衣配置：
  - 可选面料。
  - 可选花纹。
  - 可选颜色范围。
  - 可加印位置和内容类型。
- 预览区：展示当前配置下前台设计页会开放哪些能力。
- 操作按钮：保存配置、重置、预览前台效果。

验收标准：

- 能为不同球衣配置不同可定制范围。
- 成品球衣不能开放整体面料、花纹和配色。
- 白板球衣可以开放面料、花纹和配色。
- 配置结果能影响前台设计页展示的可选项。

#### 2.5.2 多客户专属产品配置页

目标：为不同客户配置专属可见产品、价格和默认设计范围。

核心内容：

- 客户列表：客户名称、客户类型、联系人、状态。
- 专属产品配置：
  - 给客户分配可见球衣。
  - 设置客户专属价格。
  - 设置客户专属起订量。
  - 设置客户默认 Logo、默认队名、默认配色。
  - 设置是否允许该客户使用成品球衣或白板球衣。
- 搜索和筛选：按客户、产品类型、状态筛选。
- 操作按钮：新增客户、编辑配置、启用/停用、预览客户前台。

验收标准：

- 能模拟多个客户各自拥有不同产品范围。
- 能展示客户专属价格和默认配置。
- 能区分通用产品和客户专属产品。

#### 2.5.3 用户订单生产信息查看和下载页

目标：让管理端查看用户提交的团定订单，并下载可用于生产的订单信息。

核心内容：

- 订单列表：订单号、客户、产品、产品类型、总件数、订单金额、提交时间、生产状态。
- 订单详情：
  - 球衣款式和统一设计配置。
  - 成品/白板产品类型。
  - 多位置加印明细。
  - 团队名单：队员姓名、号码、尺码、数量。
  - 收货信息和备注。
  - 生产注意事项。
- 下载能力：
  - 下载生产明细 CSV。
  - 下载订单 JSON。
  - 下载前台预览图或占位预览图。
- 状态操作：待确认、待生产、生产中、已完成。

验收标准：

- 能查看订单的完整可生产信息。
- 能下载包含团队名单和加印信息的生产明细。
- 能按订单状态筛选。
- 生产信息中的姓名、号码、尺码、数量和加印位置清楚可读。

## 3. 推荐技术方案

前端：

- Vite
- React
- TypeScript
- React Router
- Zustand 或 React Context 管理设计配置
- 伪 3D 预览使用 HTML + CSS + 图片/图层叠加实现

样式：

- CSS Modules、Tailwind CSS 或普通 CSS 均可。
- DEMO 优先保证视觉统一、页面完整、交互清楚。

数据：

- 使用本地 mock 数据。
- 暂不接后端接口。
- 订单提交使用本地模拟。

## 4. 路由设计

- `/jerseys`：球服列表页
- `/jerseys/:id`：球服详情页
- `/designer/:id`：3D 球服设计页
- `/checkout`：下单页
- `/order-success`：模拟下单成功页，可作为下单页的提交结果状态
- `/admin/customization-rules`：管理端，球衣可定制范围配置页
- `/admin/customer-products`：管理端，多客户专属产品配置页
- `/admin/orders`：管理端，用户订单生产信息查看和下载页
- `/admin/orders/:id`：管理端，订单生产详情页

## 7. 价格规则

基础规则：

- 球服基础价：来自商品数据。
- 成品球衣：基础价较高，只计算指定位置加印费用。
- 白板球衣：基础价较低，额外计算面料、花纹、配色和指定位置加印费用。
- 每个文字位置：+10。
- 每个号码位置：+10。
- 每个图案位置：+15。
- 白板面料升级：+15。
- 白板复杂花纹：+20。
- 单件价格 = 球服基础价 + 统一设计费用 + 多位置加印费用。
- 总件数 = 团队名单中每一行数量相加。
- 总价 = 单件价格 * 总件数。

DEMO 阶段只需在前端计算，不需要服务端校验。

## 8. 视觉方向

整体风格：

- 运动、专业、清爽。
- 页面以商品和 3D 设计器为主，避免做成营销落地页。
- 列表页偏电商浏览体验。
- 设计页偏工具型布局，左侧/右侧控制面板，中间伪 3D 预览。
- 设计页要明确区分“成品加印”和“白板设计”，让用户知道当前哪些项目可改、哪些不可改。
- 下单页偏团队订购表格体验，名单录入和总价统计要清楚。

建议配色：

- 背景：浅灰或白色。
- 主色：黑色、亮蓝或荧光绿作为运动感强调色。
- 状态色：成功绿色、错误红色、提示黄色。

## 9. 简单版设计规范

参考市面上常见球服定制网站的页面习惯，本 DEMO 视觉目标是“简单大方、浅色主题、工具清晰”。整体不要做成炫酷营销页，重点让用户快速完成选款、设计和团定下单。

### 9.1 视觉关键词

- 浅色主题：白色、浅灰为主，避免大面积深色背景。
- 专业运动感：用少量高对比强调色体现运动属性。
- 信息清楚：商品、设计配置、价格、团队名单优先级明确。
- 操作直接：按钮、筛选、表单、颜色选择器都要一眼能懂。
- 页面克制：少用大面积渐变、复杂装饰和过度动效。

### 9.2 色彩规范

基础色：

- 页面背景：`#F6F7F9`
- 内容背景：`#FFFFFF`
- 主文字：`#111827`
- 次级文字：`#6B7280`
- 边框线：`#E5E7EB`
- 分割线：`#EEF0F3`

品牌强调色：

- 主按钮/重点操作：`#2563EB`
- 运动强调色：`#22C55E`
- 当前选中态：`#DBEAFE`
- 危险/删除：`#EF4444`
- 提示/警告：`#F59E0B`

使用要求：

- 页面主体保持浅色和留白。
- 强调色只用于主按钮、选中态、价格、关键状态。
- 同一页面不要同时使用过多高饱和颜色。
- 球服颜色选择器可以展示丰富颜色，但不能影响整体 UI 的清爽感。

### 9.3 字体与排版

- 字体：系统默认无衬线字体即可。
- 页面标题：24-32px，字重 700。
- 区块标题：18-20px，字重 600。
- 正文：14-16px。
- 辅助说明：12-13px，使用次级文字色。
- 数字价格：18-24px，字重 700，可使用主按钮色或主文字色。
- 行高保持宽松，表单和表格优先保证可读性。

### 9.4 布局规范

通用布局：

- 顶部导航固定在页面上方或自然置顶，高度 64px 左右。
- 页面最大内容宽度建议 1200-1280px。
- 页面左右留白桌面端 24-32px，移动端 16px。
- 卡片圆角不超过 8px。
- 内容块之间使用 16-24px 间距。

列表页：

- 上方为筛选和排序区域。
- 下方使用 3-4 列商品网格。
- 商品卡片突出球衣图片、产品类型、价格和“开始设计”按钮。
- 成品球衣和白板球衣要有清晰标签。

详情页：

- 左侧商品图片，右侧商品信息和定制范围。
- 明确展示“成品球衣”或“白板球衣”。
- 成品球衣说明可加印位置。
- 白板球衣说明可选面料、花纹和配色。
- 主操作按钮为“开始定制”。

设计页：

- 中间或左侧为伪 3D 球服预览区。
- 右侧为设计控制面板。
- 控制面板按步骤分组：
  - 成品球衣：加印位置 -> 内容类型 -> 手动输入文字/号码或选择图案 -> 样式设置。
  - 白板球衣：面料 -> 花纹 -> 配色 -> 加印位置 -> 内容设置。
- 价格摘要固定在控制面板底部或右下区域。
- “下一步下单”始终保持明显。

下单页：

- 上方显示统一设计摘要。
- 中间展示团队名单表格。
- 右侧或底部展示价格汇总。
- 团队名单表格是页面核心，行高、输入框和删除按钮要清楚。

管理端：

- 使用更克制的后台工具布局，不做营销式大图。
- 左侧或顶部提供管理端导航：可定制范围、客户产品、生产订单。
- 配置页以表单、表格、开关、标签和预览区为主。
- 订单生产页重点保证信息密度和可读性。
- 下载按钮、状态筛选和订单详情入口要明显。

### 9.5 组件规范

按钮：

- 主按钮：蓝底白字，用于开始设计、下一步下单、提交订单。
- 次按钮：白底灰边，用于返回、重置、保存草稿。
- 危险按钮：红色文字或红色描边，用于删除队员行。

卡片：

- 使用白底、浅灰边框、轻微阴影或无阴影。
- 卡片圆角 8px。
- 不做多层嵌套卡片。

表单：

- 输入框高度 40-44px。
- 边框使用浅灰，聚焦时使用主按钮蓝。
- 错误提示放在输入框下方，使用红色小字。

选择器：

- 颜色选择使用圆形或方形色块，选中时加蓝色描边。
- 面料和花纹使用小缩略图或简洁标签。
- 加印位置使用球衣小示意图或位置按钮。

表格：

- 表头浅灰背景。
- 每行包含队员姓名、号码、尺码、数量、小计、操作。
- 支持快速新增一行、复制上一行、删除当前行。
- 移动端可改为队员信息卡片，避免表格横向溢出。

### 9.6 交互状态

- 加载状态：使用简单骨架屏或浅灰占位，不使用复杂动画。
- 空状态：用简短文案说明下一步操作。
- 禁用状态：降低透明度并禁止点击。
- 选中状态：蓝色描边或浅蓝背景。
- 错误状态：红色边框 + 简短错误提示。
- 成功状态：绿色状态提示或成功弹窗。

### 9.7 图片与预览规范

- 商品图片保持干净背景，球衣占画面主体。
- 伪 3D 预览不追求真实交互，但要有立体观感。
- 成品球衣预览必须保持固定底图，不允许改整体配色。
- 白板球衣预览要能明显看到面料、花纹和配色变化。
- 多位置加印要能在预览图上看到对应位置变化。

### 9.8 响应式要求

- 桌面端优先，保证演示效果完整。
- 平板端设计页可以上下布局：预览在上，控制面板在下。
- 手机端列表页改为单列或双列。
- 手机端下单页团队名单可改为卡片式编辑。
- 所有按钮文字不能溢出，表格不能强行撑破页面。

### 9.9 参考观察

- 常见定制站会突出颜色、文字、号码、Logo/图案上传和预览区域。
- 队服类业务通常需要名单、尺码、号码等批量录入能力。
- 定制器页面通常采用“预览区 + 控制面板 + 价格/下一步”的工具型布局。
- 本 DEMO 只取这些共性做轻量实现，不需要完整复刻复杂在线设计器。

## 10. DEMO 边界

本阶段不做：

- 登录注册。
- 真实支付。
- 后端订单接口。
- 真实库存。
- 复杂 3D 布料模拟。
- 真实 3D 模型交互。
- 真实模型贴图和 UV 展开。
- 生产级图片上传和抠图。
- 多语言。
- 真实权限系统。
- 真实客户账号体系。
- 真实生产系统对接。

可选增强：

- 保存设计到 localStorage。
- 导出设计截图。
- 移动端简化 3D 控制面板。
- 预设球队配色模板。

## 11. 最小可演示流程

1. 用户进入球服列表页。
2. 用户选择成品球衣或白板球衣并进入详情页。
3. 用户点击开始 3D 定制。
4. 如果是成品球衣，用户在指定位置加图案，并手动输入文字和号码。
5. 如果是白板球衣，用户先选择面料、花纹和配色，再在指定位置加图案，并手动输入文字和号码。
6. 用户进入下单页确认统一设计配置。
7. 用户录入多名队员的尺码、姓名、号码和数量。
8. 用户填写联系人和收货信息并提交模拟订单。
9. 页面显示下单成功结果。

## 12. 初步工期拆分

- 第 1 天：项目骨架、路由、mock 数据、基础布局。
- 第 2 天：列表页、详情页。
- 第 3-4 天：伪 3D 设计页核心交互。
- 第 5 天：下单页、模拟订单、流程联调。
- 第 6 天：管理端三页、模拟配置和下载。
- 第 7 天：视觉优化、响应式、演示检查。
