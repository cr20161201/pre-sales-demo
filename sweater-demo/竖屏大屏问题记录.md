# AI 推荐找款试衣竖屏大屏问题记录

## 1. 当前版本定位偏差

当前 `sweater-screen.html` 是第一版竖屏落地大屏，但实际表现仍然带有较强的网页 / 手机页面思路，没有完全符合商场竖屏大屏的使用场景。

竖屏落地屏不是手机 APP，也不是横屏后台的竖向改版。它应该是一个站立操作的门店导购终端，重点是：

- 远距离一眼看懂
- 中上部完成主要触控
- 低处不放关键操作
- 信息少而清楚
- 试穿与推荐流程要像门店导购，而不是表单页面

## 2. 已发现问题

### 2.1 首页信息不聚焦

当前首页存在以下问题：

- 底部店铺地址是废信息，用户还没有进入具体任务，不需要看到店铺位置。
- 小程序码不应该出现在首页，用户还没有形成扫码动机。
- 首页看起来像功能菜单加门店信息条，不够像吸引用户停下来的落地屏。
- 两个功能入口虽然明确，但主视觉和入口关系还不够高级。

首页应该只回答两个问题：

```text
这是做什么的？
我现在可以点什么？
```

首页建议保留：

- `AI 推荐找款试衣`
- 一句价值说明
- 大主视觉
- 两个入口：`AI动态试穿`、`帮我推荐`

首页建议移除：

- 店铺地址
- 小程序码
- `门店互动屏`
- 过多状态标签
- 过多说明文字

### 2.2 状态标签无意义

当前页面右上角出现：

```text
门店互动屏
实时推荐
```

这些文案不是用户任务，也不是必要产品信息，容易显得像 demo 标签或系统装饰。

建议删除。第一版不需要右上角状态标签。

### 2.3 AI动态试穿不应自动轮播

用户明确：`AI动态试穿` 不是图片轮播。

当前页面使用自动轮播切换款式，这会让体验变成看图集，而不是数字试衣镜。

正确方向：

- 当前款式由用户点选。
- 用户点哪件，试穿画面才切换哪件。
- 不自动轮播。
- 即使现在素材是静态图，也应按“动态试穿画面区域”来设计，不表现成图片轮播。

### 2.4 关键操作位置过低

当前试穿页把款式货架放在底部。对于 55 寸、65 寸竖屏落地大屏，底部区域需要用户低头、弯腰，甚至蹲下操作。

落地屏应遵循人体工学操作区：

```text
顶部 0% - 18%：标题、返回、弱状态
中上部 18% - 68%：主要操作区
底部 68% - 100%：展示信息、弱信息、二维码
```

关键操作不应放在底部，包括：

- 款式切换
- 生成推荐
- 下一套 / 上一套
- 查看试穿

### 2.5 AI动态试穿页布局需要重排

当前布局：

```text
顶部标题
中部大试穿图 + 信息
底部款式货架
```

问题：

- 款式货架太低。
- 右侧信息卡较高但内容少，产生空白。
- 店铺信息抢占试穿页空间。
- 右上角状态标签无意义。

建议改为：

```text
顶部：返回首页 + AI动态试穿

主体：
左侧：动态试穿画面区域
右侧上部：当前款式信息
右侧中部：款式选择网格
右侧下部：扫码查看当前款
```

规则：

- 不自动轮播。
- 款式选择放在右侧中部，不放底部。
- 二维码恢复，但只针对当前款。
- 店铺地址可以弱化为一句：`可到店试穿：2楼206商铺`。

### 2.6 店铺二维码丢失

当前讨论中明确：二维码不能没有。

二维码应该出现的位置：

- `AI动态试穿` 页：扫码查看当前款。
- `推荐结果` 页：扫码保存搭配 / 查看款式详情。

二维码不应该出现的位置：

- 首页。
- 推荐选择页。

### 2.7 帮我推荐页像手机页面

当前 `帮我推荐` 页是三组大按钮纵向排列，表现像手机表单的放大版。

问题：

- 页面不够像门店导购终端。
- 问题和选择项垂直堆叠，容易把操作推到低处。
- 缺少大屏应有的导购感和视觉预览。

正确方向：

`帮我推荐` 应该像门店导购问答屏，而不是手机表单。

建议结构：

```text
帮我推荐

左侧：导购问题和当前选择
中部：大按钮选项
右侧：款式候选 / 推荐预览
中部偏下：生成搭配
```

保留三组条件：

```text
场景：通勤上班 / 周末休闲 / 约会聚餐 / 旅行拍照
风格：简约 / 甜美 / 复古 / 松弛
颜色：浅色 / 彩色 / 中性色 / 深色
```

但不要做成从上到下的手机表单。

### 2.8 推荐结果页转化信息位置需要明确

推荐结果页才适合承接店铺和二维码信息。

建议保留：

- 推荐标题
- 主推款式
- 搭配组合
- 推荐理由
- `查看试穿`
- `上一套` / `下一套`
- 店铺地址
- 小程序码

操作按钮应放在中部，不要放到底部。

二维码和地址可以放在底部或右下，因为扫码不是屏幕触控动作。

## 3. 下一版设计原则

### 3.1 页面不要像手机

竖屏大屏不能把手机页面放大。按钮可以大，但布局要符合站立操作和远距离阅读。

### 3.2 首页不做转化

首页只做吸引与分流：

```text
AI动态试穿
帮我推荐
```

地址和二维码放到用户看到具体款式或推荐结果之后。

### 3.3 关键操作集中在中上部

所有需要触摸的关键操作都应放在屏幕中上部或中部。

底部只能放：

- 弱提示
- 店铺信息
- 二维码
- 非关键展示信息

### 3.4 AI动态试穿是工作台，不是轮播

试穿页应像“数字试衣镜”：

- 用户点选款式
- 画面切换当前试穿效果
- 可扫码查看当前款

不做自动轮播。

### 3.5 推荐页是导购问答，不是表单

`帮我推荐` 应该像店员提问，而不是填写筛选表。

问题、选择、预览、生成按钮需要组成一个大屏导购面板。

## 4. 建议页面结构

### 4.1 首页

```text
AI 推荐找款试衣
找到适合你的上身效果与搭配方案

[大主视觉]

[AI动态试穿] [帮我推荐]
```

不显示：

- 店铺地址
- 二维码
- 门店互动屏
- 实时推荐

### 4.2 AI动态试穿页

```text
首页        AI动态试穿

左侧：
  动态试穿画面区域

右侧：
  当前款式
  款式信息
  款式选择网格
  扫码查看当前款
```

规则：

- 不自动轮播。
- 款式选择在右侧中部。
- 二维码恢复。
- 店铺地址弱化。

### 4.3 帮我推荐页

```text
首页        帮我推荐

你今天想找什么样的款式？

场景选择
风格选择
颜色选择

推荐预览

[生成搭配]
```

规则：

- 不做手机式纵向表单。
- 生成按钮放在中部操作区。
- 可以配款式候选图或当前选择预览。

### 4.4 推荐结果页

```text
首页        为你推荐

主推款式
搭配组合
推荐理由

[上一套] [下一套] [查看试穿]

可到店试穿
小程序码
```

规则：

- 操作按钮放中部。
- 二维码和店铺地址放底部或右侧下部。

## 5. 下一版调整清单

- 删除首页底部地址和小程序码。
- 删除所有 `门店互动屏`、`实时推荐`、`试穿中` 等状态标签。
- 首页重做为主视觉 + 两个入口。
- 取消 AI 试穿自动轮播。
- 试穿页款式选择从底部移到右侧中部。
- 试穿页恢复当前款二维码。
- 推荐选择页从手机式表单改为大屏导购面板。
- 推荐结果页集中展示店铺信息和二维码。
- 所有关键操作控制在屏幕 18% - 68% 高度范围内。

## 6. 2026-06-09 确认方向

本节记录后续改版以客户和现场反馈确认后的方向为准。前文保留问题背景，但实际执行优先参考本节。

### 6.1 设备与布局基准

实机是 85 寸竖向落地安装屏，分辨率确定为 `2160 x 3840`，使用时会进入浏览器全屏模式。

后续不再以 `1080 x 1920` 设计稿放大到 4K，而是直接按 `2160 x 3840` 原生竖屏重新布局。这样可以避免 2 倍缩放带来的字体、边框、媒体裁切和触控尺寸误差。

页面不需要都铺满到底。85 寸落地屏下方区域过低，用户需要弯腰才能看或操作，因此底部允许自然留白。关键触控操作应集中在屏幕中上部到中部。

### 6.2 只保留竖版

客户只需要竖版。后续应删除横版页面和横版入口，避免现场误开或维护时混淆。

保留竖版入口：

```text
sweater-screen.html
sweater-screen.css
sweater-screen.js
sweater-config.js
sweater-assets/
```

横版相关页面、脚本、样式和入口链接后续可以清理。

### 6.3 品类文案泛化

商城不止有毛衫，主标题统一改为：

```text
AI 推荐找款试衣
```

入口和推荐页文案尽量使用“款式”“上身效果”“搭配方案”，不要把体验限定成毛衫。

### 6.4 素材替换与媒体兼容

素材按文件名对应款式替换，款式名称也按素材名更新。当前 demo 素材包括：

```text
红色长款大衣
女士翻领黄色短袖
女士浴袍大衣
男士华夫格短袖POLO衫
诺琳兰套装
```

每个款式需要配置：

- `name` / `shortName`
- `category`
- `colors`
- `material`
- `scene`
- `imageUrl`：缩略图或商品图
- `tryOnMediaUrl`：试衣主媒体
- `tryOnMediaType`：`image` 或 `video`
- `qrCodeUrl`：当前款二维码，没有真实码时用占位

试衣时媒体要兼容静态图片和视频。有视频的款式优先展示视频，视频应设置静音、自动播放、循环、内联播放；没有视频的款式展示静态图片。

### 6.5 首页方向

首页可以顶天立地，做成大气的全屏入口页。首页是吸引和分流，不是信息页。

首页建议结构：

```text
全屏主视觉

顶部偏左：
AI 推荐找款试衣
一句短说明

中部偏下：
[AI动态试穿] [帮我推荐]
```

首页不放店铺信息，不放二维码，不放复杂商品详情。

按钮需要符合 85 寸落地屏人机工程。关键入口按钮应位于成年人自然站立伸手可触达的位置，避免过高或过低。按 `2160 x 3840` 估算，按钮区域可放在大约 `y=1550-2050`，底部 `2600px` 以下不放关键触控。

按钮应比当前版本更大、更明确。参考尺寸：

- 单个入口按钮宽约 `700-820px`
- 高约 `260-320px`
- 两个按钮间距约 `56-72px`
- 主文字约 `64-76px`
- 副文字约 `32-40px`

### 6.6 AI 动态试穿页方向

客户反馈试衣页不再采用左主右辅的左右布局，而是做成全屏数字试衣镜。试衣媒体作为全屏主画面，介绍和切换做成浮窗。

试衣页建议结构：

```text
全屏试衣媒体

顶部轻量导航：
首页 / AI动态试穿

右侧浮窗：
选择款式  1 / 3
[缩略图] [缩略图]
[缩略图] [缩略图]
[缩略图] [缩略图]
上一页 / 下一页

当前款式
款名
颜色 / 材质 / 场景

店铺信息
扫码查看当前款
二维码
```

选择款式放在当前款式信息上方，因为用户在试衣页最常做的动作是切换款式。当前款式信息和店铺信息跟随所选款式同步更新。

款式选择需要支持分页。当前 demo 数量少，但未来款式可能很多。建议每页 `2 列 x 3 行`，共 6 件。翻页只切换缩略图列表，不自动改变当前已选款式。当前页少于 6 件时自然留空；只有 1 页时上一页 / 下一页可以隐藏或置灰。

试衣页底部不放关键操作，避免用户弯腰操作。

### 6.7 推荐选择页方向

推荐选择页保持当前整体高度和居中面板的感觉即可。改 4K 时适当放大，不需要顶天立地。

推荐选择页仍然是导购问答面板：

```text
首页 / 帮我推荐

STYLE FINDER
今天想找什么样的款式？

场景
风格
颜色

[生成搭配]
```

上下左右留白可以参考当前实机截图，保持中间一块清楚的操作面板。生成按钮仍然放在中部触控区，不下沉到底部。

### 6.8 推荐结果页方向

推荐结果页保持当前页面结构，不改成试衣页那种全屏浮窗。

改 4K 时只做适当放大和位置校正：

- 内容整体居中。
- 不铺满全屏。
- 上下左右保留明显留白。
- 主内容高度控制在中上部到中部。
- 底部允许自然留白。
- 店铺信息和二维码保留在推荐结果页，用于扫码保存搭配或查看详情。

推荐结果页目前整体高度相对可以，后续不要为了填满 85 寸屏幕而把信息推到很低的位置。

### 6.9 后续实施清单

- 按 `2160 x 3840` 重建竖版布局基准。
- 删除横版页面、脚本、样式和入口链接。
- 替换新素材，按素材名更新款式名和属性。
- 给试衣媒体增加图片 / 视频兼容渲染。
- 首页改成全屏主视觉入口页，放大并重新定位两个主按钮。
- 试衣页改成全屏媒体 + 右侧浮窗。
- 试衣页款式选择增加分页。
- 当前款式信息和店铺信息跟随所选款式同步更新。
- 推荐选择页保持居中面板结构，只做 4K 适配和适当放大。
- 推荐结果页保持当前结构，只做 4K 适配和适当放大。
