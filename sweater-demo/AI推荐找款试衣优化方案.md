# AI 推荐找款试衣优化方案

## 1. 产品定位

当前体验从“试衣 / 推荐”两个功能入口，升级为一个更完整的商场大屏交互系统：

```text
主链路：DIY柔性定制
辅助链路：智能穿搭推荐
共同结果页：视频试衣 / AI上身效果展示
```

核心卖点不再只是“看上身效果”，而是突出客户更关心的柔性定制能力：

```text
从版型、织片到颜色、图案、局部改款，生成可试穿的专属款式。
```

因此首页主入口应明确突出 `DIY柔性定制`，`智能穿搭推荐` 作为辅助入口存在。

## 2. 首页优化

首页保留两个入口，但主次必须明确。

| 入口 | 优先级 | 展示方式 | 说明 |
|---|---:|---|---|
| DIY柔性定制 | 主入口 | 更大、更亮、更靠左 | 强调“从版型到织片，生成专属款式”。 |
| 智能穿搭推荐 | 次入口 | 弱一级视觉 | 强调“按条件快速推荐搭配”。 |

首页建议文案：

```text
AI 推荐找款试衣

DIY柔性定制
从版型、织片到颜色图案，生成你的专属款式

智能穿搭推荐
按季节、场景和风格，推荐适合你的搭配
```

## 3. 链路一：DIY柔性定制

`DIY柔性定制` 是第一期重点链路。

| 步骤 | 页面/功能 | 第一期范围 | 说明 |
|---|---|---|---|
| 1 | 选择版型 | 做 | 使用枚举/配置写死，如开衫、套头、POLO、外套、套装等。 |
| 2 | 选择织片 | 做 | 展示织片、纹理、工艺素材，第一期写死。 |
| 3 | 款式生产 | 做 | 选择完成后进入“AI面料上身”生成态。 |
| 4 | DIY编辑 | 做 | 提供三个方向：调整颜色、添加图案、局部改款。 |
| 5 | 视频试衣 | 做 | 复用现有试衣页，展示最终上身效果。 |

### 3.1 DIY编辑

| 功能 | 第一期范围 | 说明 |
|---|---|---|
| 调整颜色 | 做基础流程 | 包含“智能识别”和“指定颜色”。第一期可做演示态。 |
| 添加图案 | 做基础流程 | 内置图案库，按分类展示。图案数据第一期写死。 |
| 局部改款 | 做基础流程 | 涂抹 + 快捷输入。快捷项如领型、袖子、口袋、下摆。 |

局部改款快捷项示例：

| 部位 | 快捷项示例 |
|---|---|
| 领型 | 圆领、V领、翻领、高领、拉链领 |
| 袖子 | 长袖、短袖、落肩袖、灯笼袖、收口袖 |
| 口袋 | 无口袋、贴袋、侧袋、胸袋 |
| 下摆 | 直下摆、罗纹下摆、开衩、收腰 |

## 4. 链路二：智能穿搭推荐

`智能穿搭推荐` 是快速导购链路。第一期不接真实 AI 推荐。

| 步骤 | 页面/功能 | 第一期范围 | 说明 |
|---|---|---|---|
| 1 | 基础条件选择 | 做 | 季节、性别、品类。 |
| 2 | 风格条件选择 | 做 | 场景、风格、色系。 |
| 3 | 推荐结果 | 做 | 第一期通过枚举/配置模拟推荐结果。 |
| 4 | 视频试衣 | 做 | 直接进入现有视频试衣页。 |

备注：

```text
第一期推荐逻辑写死。
后续可替换为 AI 算法推荐。
不做后台推荐规则管理。
```

## 5. 视频试衣页优化

视频试衣页作为两条链路的共同结果页。

| 功能 | 第一期范围 | 说明 |
|---|---|---|
| 视频/图片试衣展示 | 做 | 兼容静态图片和视频。 |
| 右侧浮窗 | 做 | 展示款式切换、当前款信息、店铺二维码。 |
| 款式切换 | 做 | 支持分页，适配未来更多款式。 |
| 当前款信息 | 做 | 展示款名、颜色、材质、场景等。 |
| 店铺信息 | 做 | 当前款关联店铺，展示店铺名称、档口、二维码。 |

视频试衣页不是首页入口本身，而是两条链路的结果承接页：

```text
DIY柔性定制 → 款式生产 / DIY编辑 → 视频试衣
智能穿搭推荐 → 条件选择 → 推荐结果 → 视频试衣
```

| 后台模块 | 用途 |

## 11. 试衣页待改记录

### 11.1 DIY 来源隐藏商铺信息

当用户从 `DIY柔性定制` 链路进入 `AI试穿` 页面时，右侧浮层底部不再展示商铺信息。

当前需要移除的内容：

```text
2楼206商铺
扫码查看当前款详情
小程序码 / 二维码
```

替换为一个主按钮：

```text
上传文件生成
```

交互规则：

- 从 DIY 进入试穿：显示 `上传文件生成`。
- 从首页商品 / 智能穿搭推荐进入试穿：保留商铺信息和二维码。
- 第一版按钮可以先做演示态，例如点击后显示“文件生成中”或“已生成款式文件”。

实现判断建议：

```text
state.tryOnSource === "diy"
```

### 11.2 右侧浮层更透明

客户偏好更通透的玻璃质感，因此右侧浮层不要加实，应该比当前更透明。

调整方向：

- 降低浮层白底不透明度，让背景更透。
- 保留或增强玻璃模糊，避免背景细节直接干扰文字。
- 边框线可以更亮、更清楚，用来维持面板边界。
- 文字可读性通过轻微阴影、边框和层级控制解决，而不是靠加厚白底。

建议参数方向：

```text
panel background: rgba(255, 255, 255, 0.28 ~ 0.34)
border: rgba(255, 255, 255, 0.66 ~ 0.76)
backdrop-filter: blur(36px ~ 44px)
```

需要覆盖的区域：

- 右侧整体浮层
- 选择款式卡片
- 当前款式卡片
- 非 DIY 来源下的商铺信息卡片

注意：透明度提升后需要实机或截图检查文字可读性，尤其是背景人物、深色大衣、浅色毛衫上方的浮层区域。

## 12. 界面风格方向

客户对当前界面总体满意，后续不是推翻重做，而是在现有基础上统一成更接近新 iOS 的玻璃浮层风格。

关键词：

```text
高圆角
半透明
背景模糊
轻边框
柔和阴影
大留白
少文字
图像优先
icon 导航
```

这里的“背景模糊”不是把整张页面背景图模糊掉，而是指浮窗、按钮背后的内容透过玻璃层时被轻微虚化。主视觉、试穿视频、AI结果图、商品缩略图本身都保持清晰。

典型效果：

```css
background: rgba(255, 255, 255, 0.55);
backdrop-filter: blur(30px);
```

### 11.1 背景模糊使用范围

| 区域 | 背景模糊对象 | 目的 |
|---|---|---|
| 首页入口按钮 | 按钮背后的主视觉图片 | 让按钮像玻璃浮在图片上，同时文字清楚。 |
| 试穿页右侧浮窗 | 浮窗背后的试穿画面 | 浮窗不厚重，但仍能读清图和文字。 |
| 推荐选项页面板 | 面板背后的页面背景 | 让面板更轻，不像一块实心白卡。 |
| DIY工具面板 | 工具面板背后的服装/生成图 | 保持编辑区沉浸感，工具像系统控件悬浮。 |
| icon 返回按钮 | icon 按钮背后的画面 | 小按钮保持清晰，同时不打断主画面。 |

不应该模糊：

```text
主视觉大图
试穿视频 / 图片主体
AI生成结果图
商品缩略图
图案库素材图
```

### 11.2 首页风格

首页仍保持顶天立地的大屏视觉，但入口按钮要更偏 iOS 玻璃浮窗，而不是实心网页按钮。

调整原则：

| 元素 | 风格方向 |
|---|---|
| DIY柔性定制按钮 | 主入口，更亮、更清楚，但不要纯白实心，增加透明度和背景模糊。 |
| 智能穿搭推荐按钮 | 次入口，透明度更高、存在感弱一级。 |
| 按钮形态 | 高圆角、轻边框、柔和阴影、玻璃感。 |
| 文案 | 少而清楚，突出入口差异。 |

首页入口左右关系：

```text
左侧：DIY柔性定制
右侧：智能穿搭推荐
```

主入口放左侧，符合用户从左到右的阅读和触控习惯。

### 11.3 动态试衣页风格

动态试衣页保持全屏试衣画面，右侧浮窗作为辅助控制面板。

调整原则：

| 元素 | 风格方向 |
|---|---|
| 右侧浮窗 | 更贴右、更窄、更透明，像 iOS 侧边控制面板。 |
| 款式列表 | 只放图，不放“图 + 文案”。 |
| 当前款信息 | 单独放在款式列表下方。 |
| 店铺信息 / 二维码 | 放在浮窗下方，保持轻量，不抢视觉。 |

款式列表去掉文字的原因：

```text
试衣页重点是看上身效果，不是读款名。
右侧浮窗空间有限，文字会增加噪音。
款名和属性已经在当前款信息区展示，不需要重复。
```

### 11.4 推荐选项页风格

推荐选项页整体保持居中面板结构，但位置需要上移。

调整原则：

| 项目 | 方向 |
|---|---|
| 整体位置 | 上移 5% - 10% 高度。 |
| 面板风格 | 半透明玻璃面板，高圆角，轻阴影。 |
| 选项按钮 | 类似 iOS segmented control / pill chips。 |
| 选中态 | 柔和高亮或发光，不使用厚重纯色块。 |
| 导航 | 返回首页、返回上一步都使用 icon 浮窗按钮。 |

推荐链路需要两个导航按钮：

```text
返回首页
返回上一步
```

两个按钮都使用 icon，不使用大段文字按钮。建议 icon：

```text
首页：House
返回上一步：ChevronLeft
```

### 11.5 DIY页面风格

新做的 DIY 页面从一开始就按 iOS 玻璃浮层风格设计。

| 页面 | 风格方向 |
|---|---|
| 选择版型 | 大图卡片，少文字，高圆角玻璃浮层。 |
| 选择织片 | 纹理 / 织片图片优先，弱化长文案。 |
| AI四图结果 | 4 张结果图组成候选网格，图像优先。 |
| DIY编辑 | 颜色、图案、局部改款做成侧边或底部浮窗工具面板。 |
| 图案库 | 分类展示，素材图清晰，不做模糊。 |

AI生成结果统一取 4 张候选图：

```text
AI生成 → 展示4张结果 → 用户点击选择1张 → 进入后续AI逻辑
```

点击一张结果后，再基于该结果继续执行：

```text
调整颜色
添加图案
局部改款
视频试衣
```

选中态建议使用轻量效果：

```text
发光描边
轻微放大
高亮玻璃边框
```

避免使用厚重蓝色边框或传统网页选中态。

### 11.6 全局视觉参数建议

| 项目 | 建议 |
|---|---|
| 浮窗背景 | `rgba(255, 255, 255, 0.45 - 0.72)` |
| 背景模糊 | `backdrop-filter: blur(24px - 40px)` |
| 圆角 | `36px - 64px` |
| 边框 | `1px rgba(255, 255, 255, 0.35 - 0.6)` |
| 阴影 | 大范围、低透明度、柔和扩散 |
| 按钮 | 大触控面积，icon + 短文案 |
| 文案 | 少而清楚，不做长段说明 |

### 12.1 款式与织片选择

| 问题 | 修改方向 |
|---|---|
| 当前选择款式、选择织片的选中态不明显 | 加强选中态：明显描边、勾选标记、轻发光或高亮底色，让用户明确知道当前已选项。 |
| 选择款式和选择织片希望接近图 1 的浮窗质感 | 后续页面结构可向“大图预览 + 浮窗工具列表”靠拢，但仍保持操作清晰、触控区域大。 |
| 款式素材原始尺寸不统一导致显示大小不一致 | 款式类图片统一放入固定展示框，使用同一套显示规则，不针对单张图做特殊放大或裁剪。 |
| DIY 进入后显示的款式图过大，袖子被裁切 | 不是屏幕尺寸问题，主要是 `cover` 裁切导致。DIY 相关款式图应完整显示，衣服完整优先。 |

款式类图片统一规则：

```text
选择款式页
DIY编辑页当前款式预览
AI生成结果页
继续设计时展示的款式图
```

以上都使用统一展示框和统一显示规则，不做单张素材特殊处理。素材准备侧也应尽量统一尺寸、留白和角度。

### 12.2 DIY 编辑页图片显示

DIY 编辑页、AI 生成结果页、款式选择预览页都属于“看设计”的场景，不是首页背景或试衣沉浸页。

因此显示原则是：

| 场景 | 显示策略 |
|---|---|
| 首页 / 试衣页背景 | 可以使用铺满画面的沉浸显示。 |
| DIY 编辑页 | 服装完整优先，避免袖子、下摆被裁切。 |
| AI 生成结果页 | 4 张候选图统一尺寸展示，优先让用户比较款式。 |
| 选择款式页 | 所有款式图统一尺寸显示，不因素材尺寸不同而忽大忽小。 |

### 12.3 图案工具

图案工具需要支持分类和分页，避免后续图案库变多后撑爆浮窗。

| 项目 | 修改方向 |
|---|---|
| 图案分类 | 预计 8-10 个分类，可横向分页或滚动。 |
| 分类下图案数量 | 每类可能超过 10 个。 |
| 图案展示 | 固定 2 列，使用偶数数量分页。 |
| 图案分页 | 每页建议 6 或 8 个，使用左右 icon 翻页。 |
| 层级 | 先选分类，再选图案，当前分类和当前图案都要有明显选中态。 |

图案工具重点不是把所有图案一次铺满，而是：

```text
分类清楚
每页整齐
选中明确
后续数量变多也能扩展
```

### 12.4 局部改款工具

局部改款仍保持当前小浮窗结构，不改成大面积左右编辑器。

确认结构：

```text
DIY编辑页
  右侧玻璃浮窗
    颜色 / 图案 / 局部 三个 tab
```

局部 tab 内部优化：

| 区域 | 修改方向 |
|---|---|
| 上方区域 | 不叫“涂抹区域”，改为“预览调整”。 |
| 预览调整 | 做成可点击模块。未预览时提示“未预览调整时，将自动识别替换服装”。 |
| 点击预览调整 | 弹出涂抹交互示意，用于用户圈选/涂抹要调整的位置。 |
| 涂抹完成后 | 返回当前小浮窗，并回填到“预览调整”区域，显示已预览/已选择状态。 |
| 下方快捷选项 | 做层级优化，不再把所有选项混在同一层。 |

局部快捷选项层级：

```text
第一层：修改区域
领型 / 袖子 / 口袋 / 下摆

第二层：当前区域下的快捷改法
领型：圆领 / V领 / 翻领 / 高领
袖子：长袖 / 短袖 / 落肩袖 / 收口袖
口袋：无口袋 / 贴袋 / 侧袋 / 胸袋
下摆：直下摆 / 罗纹下摆 / 开衩 / 收腰
```

视觉上要明确区分：

```text
当前修改区域
当前快捷选项
已完成预览调整状态
```

### 12.5 文案与按钮优先级

按钮文案调整：

| 位置 | 文案 |
|---|---|
| DIY 编辑页主按钮 | 生产新设计 |
| AI 生成结果页标题 | AI设计结果 |
| AI 生成结果页主按钮 | 继续设计 |
| AI 生成结果页次按钮 | 进入试穿 |

结果页优先级：

```text
重点是继续设计，试穿是次级动作。
```

因此视觉权重应为：

```text
继续设计 > 进入试穿
```

### 12.6 需要避免的点

| 避免项 | 原因 |
|---|---|
| 款式图使用铺满裁切 | 会造成袖子、下摆超出显示区域。 |
| 针对某一张款式图单独调尺寸 | 后续素材一多会难维护。 |
| 图案库一次性全铺开 | 分类和分页会失控。 |
| 局部改款所有按钮同层平铺 | 用户不清楚是先选区域还是先选改法。 |
| 按钮叫“生成4张AI结果” | 太工程化，不适合客户演示。 |
