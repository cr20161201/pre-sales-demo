# AI Fashion Demo 设计规范

## 1. 设计方向

本 demo 的视觉方向是浅灰底的极简时装图录，而不是黑底科技风或传统电商风。APP 端参考移动端 fashion lookbook / showroom，PC 后台保持同一套视觉语言，但更强调信息效率和审核操作。

关键词：

```text
minimal fashion catalog
mobile showroom
light editorial dashboard
AI fitting room
quiet luxury
image first
```

## 2. 跨端设计原则

APP 与后台使用同一套基础视觉语言：

- 白 / 浅灰背景
- 黑白灰为主
- 图片优先，文字克制
- 低饱和状态色
- 细线分隔
- 弱阴影或无阴影
- 控件小而清晰
- 不使用强科技感渐变
- 不使用大面积彩色按钮
- 不使用传统促销电商视觉

APP 端更沉浸，PC 后台更高信息密度。

## 4. 字体

### 4.1 字体策略

为了接近时装图录气质，标题可使用系统 serif，正文使用系统 sans-serif。

推荐：

```css
--font-display: Georgia, "Times New Roman", serif;
--font-body: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

## 5. APP 移动端规范

### 5.1 画布

移动端页面按 iPhone 竖屏比例设计：

- 推荐宽度：`390px`
- 推荐高度：`844px`
- 背景：浅灰
- 内容不使用厚重卡片
- 图片直接放置在背景中

### 5.2 首页布局

首页采用 Lookbook 网格：

- 顶部：轻量导航，左侧 Looks / Items，右侧菜单图标
- 内容：两列人物 / 单品图
- 底部：Home / Create / Profile
- 中间 Create 按钮使用黑色小方形或圆角方形

布局参考：

```text
Top nav
Looks   Items                         menu

Grid
[ Look image ] [ Look image ]
[ Look image ] [ Look image ]

Bottom nav
Home             +             Profile
```

### 5.3 试穿结果页

试穿结果页以人物试穿图为主：

- 人物大图居中
- 右侧竖向操作：喜欢、关闭 / 换一套、分享
- 左下角显示当前 Look 的商品缩略图
- 底部显示页码或轻量进度
- 避免大段说明文字

### 5.4 注册与上传流程

注册流程保持极简：

- 白 / 浅灰背景
- 单屏单任务
- 输入区留白大
- 主按钮黑底白字
- 上传照片使用图片网格
- AI 生成页使用居中 loading 和短文案

### 5.5 APP 控件

按钮：

- 主按钮：黑底白字，圆角 999px 或 8px
- 次按钮：透明或白底，黑字，细边框
- 图标按钮：黑 / 白线性图标，不加复杂背景

导航：

- 顶部导航低存在感
- 底部 tab 不使用高饱和激活色
- 当前状态可用字重或轻微透明度区分

## 6. PC 后台规范

### 6.1 总体布局

PC 后台是工作台，不做手机放大版。视觉保持浅灰、图片优先和克制控件，但信息密度更高。

推荐布局：

```text
Sidebar
  Feature menu
  Account + role switch
Main workspace
  Page header
  List page / Detail page
```

基础尺寸：

- 页面最小宽度：`1280px`
- 左侧导航：`220px-260px`
- 页面内边距：`28px-40px`
- 面板圆角：`6px-8px`
- 分割线：`1px`

后台第一版只保留两个核心页面：

- List page
- Detail page

不展示 Filter / Export。页面右上角不放重复的 `New style`。

侧边栏规则：

- 左侧上方是功能菜单。
- 左侧下方是账户区。
- Designer / Merchant 身份显示和切换放在账户区。
- 切换角色后，菜单、页面标题、列表数据随角色变化，并回到 List page。

### 6.2 设计师后台

设计师后台重点是作品和提交状态。

菜单结构：

```text
Styles
```

页面结构：

- List page：展示设计师自己的款式列表。
- List panel header：显示 `New style`。
- Detail page：展示款式图片、资料、状态和设计师操作。
- 设计师可以提交审核，但不能直接上架。
- 当前 demo 中 Designer 只保留 `Styles` 菜单。

列表样式：

- 使用 PC 表格感 row，不使用移动端卡片。
- 每行包含图片、款式名称、分类、状态、更新时间和 `View`。
- 信息列对齐，方便快速扫描提交状态。
- 状态使用小标签或小圆点，不使用大面积色块。
- 不使用厚阴影。

设计师详情操作：

- `Save draft` 作为次级展示按钮。
- `Submit review` 作为主要操作。

### 6.3 商家运营后台

商家运营后台重点是审核效率。

菜单结构：

```text
Review
Styles
Looks
Users
Designers
Orders
Analytics
Settings
```

页面结构：

- Review：展示待审核款式。
- Styles：展示完整款式管理入口，通过 Tab 区分已上架、待上架、待审核。
- Styles 默认进入已上架 Tab，优先看到已上架数据。
- Orders：展示订单列表。
- Users：先展示用户列表，点击后进入用户详情。
- User detail：展示基础信息、消费记录、试穿行为、衣橱行为、偏好标签、尺码与合身反馈。
- Analytics：展示核心指标、转化漏斗、热门款式、会员分群。
- List panel header：不显示 `New style`。
- Detail page：展示款式图片、资料、状态和审核操作。
- Looks、Designers、Settings 使用轻量内容页。

列表样式：

- 使用宽屏自适应列表。
- 每行包含图片、款式名称、设计师 / 分类、状态、提交时间和 `View`。
- Merchant 需要能通过 Tab 快速切换款式状态，Tab 上展示对应数量。
- 不使用卡片瀑布流或窄列布局。

商家运营详情操作：

- `Approve and list`：黑色主按钮。
- `Request changes`：白底描边按钮。
- `Reject`：低权重描边或文字按钮。

### 6.4 后台表单

表单样式：

- Label 小字号，深灰
- Input 背景白色或浅灰白
- 边框 `#c9c9c4`
- Focus 使用黑色边框
- 不使用蓝色默认焦点
- 下拉、标签、尺寸选择保持细线风格

表单字段顺序：

1. 款式名称
2. 分类
3. 品牌 / 设计师
4. 价格
5. 颜色
6. 尺码
7. 材质
8. 风格标签
9. 设计师备注
10. 图片素材

## 7. 图片规范

图片是整个产品的主视觉。

APP：

- 人物图尽量完整露出
- 背景使用浅灰或白色
- 避免强裁切
- Look 图片优先展示整身
- Item 图片优先展示单品正面
- Item / Style 图片使用完整展示，不裁掉款式主体

后台：

- 审核详情必须有大图预览
- 后台详情中的款式图使用完整展示
- 支持查看细节图
- 商品列表缩略图也尽量完整展示款式主体
- 缺失素材使用浅灰占位，不使用彩色插画

占位图风格：

- 浅灰底
- 细线图标
- 简短说明

## 8. 组件规范

### 8.1 按钮

主按钮：

```css
background: #050505;
color: #ffffff;
border: 1px solid #050505;
border-radius: 999px;
```

次按钮：

```css
background: transparent;
color: #111111;
border: 1px solid #b8b8b2;
border-radius: 999px;
```

危险按钮：

```css
background: transparent;
color: #8f2d2d;
border: 1px solid #8f2d2d;
border-radius: 999px;
```

### 8.2 标签

状态标签：

- 高度：`22px-26px`
- 字号：`11px-12px`
- 圆角：`999px`
- 背景低饱和
- 文字颜色使用状态色

### 8.3 卡片 / 面板

APP：

- 尽量不用卡片
- 图片直接排列
- 必要信息可使用透明叠层或底部小字

PC：

- 面板用于表单、详情、审核信息
- 圆角不超过 8px
- 边框优先于阴影
- 不做卡片套卡片

### 8.4 图标

使用线性图标：

- menu
- plus
- heart
- share
- close
- upload
- search
- filter
- chevron
- check

图标按钮需要有 hover / active 状态。陌生图标需要 tooltip。

## 9. 响应式规则

### 9.1 APP

APP 端优先按固定手机画布展示。如果在桌面浏览器中演示，页面居中显示手机容器。

规则：

- 手机容器最大宽度 `430px`
- 高度使用视口高度
- 底部导航固定
- 图片网格两列
- 详情页图片优先保持完整人物比例

### 9.2 PC 后台

PC 后台适配桌面浏览器。

规则：

- 1280px 以上使用完整 sidebar + workspace 布局
- 1024px-1279px 可压缩左侧导航和列表列宽
- 低于 1024px 可切换为单栏堆叠，但第一版 demo 可不重点优化

## 10. 交互状态

所有关键操作需要有明确状态。

APP：

- 上传中
- AI Twin 创建中
- 生成试穿中
- 已收藏
- 生成失败

后台：

- 保存草稿中
- 提交审核中
- 审核通过成功
- 要求修改成功
- 驳回成功
- 表单校验错误

状态反馈风格：

- 优先使用轻量 toast
- 不使用强彩色弹窗
- 错误提示使用暗红色文字

## 11. 不使用的风格

为了保持方向统一，第一版避免：

- 黑底科技风
- 霓虹绿 / 紫色渐变
- 大面积品牌色
- 传统电商促销标签
- 复杂阴影
- 玻璃拟态
- 卡片堆叠
- 蓝色 SaaS 后台风
- 卡通插画
- 过度圆角
