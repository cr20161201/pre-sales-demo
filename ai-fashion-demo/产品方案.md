
## 1. 项目定位

本 demo 是一个包含移动端 APP 与 PC 后台的 AI 时装穿搭 / 试穿原型。核心目标是演示用户浏览 Looks / Items、创建 AI 搭配、查看试穿结果，以及设计师提交款式、商家运营审核上架的基础闭环。

当前版本重点不是完整电商交易，而是：

- 用户端的 Lookbook 浏览体验
- AI fitting model 选择
- AI 款式推荐
- 上装 / 下装选择
- 多套试穿结果切换
- 衣橱入口
- 后台款式列表与详情审核

界面视觉保持浅灰底、白灰面板、黑白灰控件、图片优先的 fashion showroom 风格。所有可见产品界面文案使用英文，不出现 `Demo`、`OTP`、`mock`、`local image`、实现说明或测试暗号类文案。

## 2. 核心角色

### 2.1 APP 用户

用户是最终消费者，主要完成浏览、注册、AI 试穿、保存款式和查看衣橱。

核心能力：

- 浏览 Looks / Items
- 首次进入 Profile 时触发注册流程
- 创建基础 fitting profile
- 上传自拍与全身照
- 设置偏好
- 选择 fitting model
- 进入 AI 款式推荐
- 选择上装 / 下装
- 查看多套试穿结果
- 保存到 Wardrobe

### 2.2 设计师

设计师是后台供给角色，负责提交自己的款式或单品，但不能直接上架。

核心能力：

- 查看款式列表
- 新增款式入口
- 查看款式详情
- 提交审核

### 2.3 商家运营

商家运营是后台审核角色，负责审核设计师提交的款式，并决定是否进入商品池。

核心能力：

- 查看审核列表
- 查看款式详情
- 审核通过并上架
- 要求修改
- 驳回

## 3. 用户端 APP 流程

### 3.1 入口与首页

APP 打开后直接进入 Home 的 Looks 页面，不默认进入注册页。

首页只保留两个主 Tab：

```text
Looks | Items
```

规则：

- `Looks / Items` 只属于 Home 页面内容，不是全局固定顶部导航。
- 进入详情页、试穿页、衣橱页、Profile 页后，不显示 Looks / Items 顶部 Tab。
- 底部导航保持：

```text
Home     +     Profile
```

首页右上角为三横线 Menu icon。Menu 中保留 Wardrobe 入口，进入独立 Wardrobe 页面。

### 3.2 Looks 首页

Looks 页面是单一 Look 列表，不做复杂推荐区。

Look 卡片：

- 展示 Look 图片
- 展示 Look 名称
- 不显示 items 数量
- 不显示价格

点击 Look 进入 Look 详情页。

### 3.3 Items 首页

Items 页面是单一 Item 列表。

Item 卡片：

- 展示单品图片
- 展示单品名称
- 展示价格
- 不显示设计师名

Items 可以通过 Menu 的 Category 做简单分类入口，当前第一版不重点实现复杂筛选。

### 3.4 首次 Profile 与注册流程

用户默认未注册，但不在打开 APP 时强制注册。

规则：

```text
第一次点击 Profile
  -> 进入注册 / onboarding 流程
  -> 完成后回到 Home

第二次点击 Profile
  -> 进入 Profile 落地页
```

注册流程：

1. 输入邮箱
2. 填写基础信息
   - 姓名
   - 年龄
   - 性别
   - 身高
   - 体重
   - 可选体型
3. 上传照片
   - 自拍
   - 全身照
4. 设置偏好
   - 品牌
   - 颜色
   - 风格
5. 创建 fitting profile

注意：

- 界面不显示 OTP 暗号。
- 界面不出现 demo/mock/local image 等实现说明。
- 当前版本使用预置 model 资产表现上传后的形象结果，但界面文案按真实产品表达。

### 3.5 Profile 落地页

Profile 是账户入口，不直接展开注册资料。

页面内容：

- 用户头像
- `Profile`
- 用户姓名
- 邮箱
- 三个同权重按钮：

```text
Wardrobe
Orders
Info
```

规则：

- 三个按钮均为白底黑字细边框，同等视觉权重。
- `Wardrobe` 可进入独立 Wardrobe 页面。
- `Orders` 和 `Info` 只保留可点击样式，不实现点击效果。
- 注册资料信息未来放入 Info 页面，当前不展开实现。

### 3.6 Wardrobe 页面

Wardrobe 是独立页面，不再嵌在 Profile 内。

当前版本不做业务联动，不根据收藏动态变化。页面直接内置展示款式列表。

页面内容：

- 返回 icon
- `Wardrobe`
- 2 列款式列表
- 款式图使用 `picture/styles`

规则：

- Wardrobe 展示的是保存/衣橱概念下的单品款式。
- 第一版不实现 Orders / Info。

## 4. Look 与 Item 详情页

### 4.1 Look 详情页

Look 详情页保持干净，突出 Look 主图。

页面内容：

- 返回 icon
- Look 大图
- Look 名称
- `AI try on`
- `Add to wardrobe`

规则：

- 不显示图集缩略图。
- 不显示 `Look preview` 字样。
- 不显示价格。
- 不显示 items 数量。
- 顶部返回统一使用 icon，不使用 `Back` 文案。

### 4.2 Item 详情页

Item 详情页展示单品信息和 AI try-on 入口。

页面内容：

- 返回 icon
- 单品图片
- 分类
- 单品名称
- 设计师 / 颜色
- 尺码选择
- `AI try on`
- `Add to bag`

Item 详情页目前仍保留轻量购买入口，但不是当前 demo 的核心重点。

## 5. AI Styling / Try-on 核心流程

当前核心链路来自底部 `+` 入口，以及 Look / Item 详情的 `AI try on`。

### 5.1 从底部 `+` 进入

底部 `+` 进入 AI styling 流程。

流程：

```text
Choose fitting model
  -> Analysis transition
  -> Styling you
  -> Select top / bottom
  -> Try on styling
  -> Try-on result
```

### 5.2 Choose fitting model 页面

该页面用于确认用于试穿的形象。

建议统一使用第一版卡片样式：

```text
←

AI TWIN
Choose fitting model

[model card]
  left: uploaded / generated model image
  right:
    Alex's AI Twin
    Change model

Start styling
```

规则：

- 左侧显示用户上传/生成的 model 图片。
- 右侧不要展示身形状态，例如 `Body profile ready`、`172cm`、`neutral palette` 等，因为这些信息目前不确定。
- `Change model` 是弱化文字入口，不做实际切换。
- 主按钮为 `Start styling`。

### 5.3 Analysis transition 页面

点击 `Start styling` 后进入过渡页。

页面表达：

- 正在分析用户形象
- 正在匹配偏好
- 正在推荐可搭配款式

该页面停留短暂时间后自动进入推荐页。

### 5.4 Styling you 页面

推荐页用于让用户参与选择上装和下装。

页面结构：

```text
←

STYLING YOU

[single model avatar]

Tops
[Top 1] [Top 2] [Top 1] [Top 2] ...

Bottoms
[Bottom 1] [Bottom 2] [Bottom 1] [Bottom 2] ...

Try on styling
```

规则：

- 上方只显示一个用户上传/生成的 model 图片，不是 AI 想象图。
- model 区域使用圆形裁切，取头部和上半身位置。
- Profile 头像也使用同样的裁切方式。
- Tops 使用横向滑动列表。
- Bottoms 使用横向滑动列表。
- 上装最多选择 1 个，可不选。
- 下装最多选择 1 个，可不选。
- 如果不选，系统使用默认推荐。
- 不显示解释性文案，例如 `Choose up to 1` 或推荐规则说明。

### 5.5 Try-on result 页面

试穿结果页展示生成后的试穿结果。

页面结构：

```text
←

[large try-on result]

right actions:
  ♡ save to wardrobe
  ↗ share

bottom:
  Current look
  Top: xxx
  Bottom: xxx

  ←   1/3   →
```

规则：

- 顶部只保留返回 icon。
- 不在顶部右上角显示 `1/3`。
- 底部使用 `← 1/3 →` 控件切换多套 Look 结果。
- 多套 Look 结果不要平铺成图集。
- 右侧只保留保存到 Wardrobe 和 Share。
- 不显示 `Add styled item to bag`。

## 6. 图片资产规则

当前图片目录为：

```text
picture/looks
picture/styles
picture/model
```

使用规则：

- `picture/looks`：Look 列表、Look 详情。
- `picture/styles`：Item 列表、Item 详情、推荐页 Tops / Bottoms、试穿结果、Wardrobe 单品款式。
- `picture/model`：注册上传模拟、Profile 头像、Choose fitting model、Styling you 上方 model 区域。


### 7.1 List page

页面内容：

- Filter，按钮展示但不实现

点击列表项进入 Detail page。

### 7.2 Detail page

设计师视角：

商家运营视角：

- 图片
- 款式资料

- Request changes

### 7.3 其它后台入口

侧边栏保留按钮，但不实现功能：

- Data

## 8. 款式状态

第一版使用简化状态。

| 状态 | 含义 | 可操作角色 |
| --- | --- | --- |
| draft | Draft | Designer |
| pending_review | Pending | Merchant |
| changes_requested | Changes requested | Designer / Merchant |
| rejected | Rejected | Designer / Merchant |
| listed | Listed | Merchant |
| unlisted | Unlisted | Merchant |

状态流转：

```text
draft -> pending_review
pending_review -> listed
pending_review -> changes_requested
pending_review -> rejected
changes_requested -> pending_review
listed -> unlisted
unlisted -> listed
```

## 10. 演示剧情

推荐演示顺序：

1. 打开 APP，直接进入 Looks。
2. 点击 Profile，首次触发注册流程。
3. 完成基础信息、照片、偏好和 fitting profile 创建。
4. 回到 Home。
5. 点击底部 `+`。
6. 选择 fitting model。
7. 进入分析过渡页。
8. 进入推荐页，选择 1 个 Top 和 / 或 1 个 Bottom。
9. 点击 Try on styling。
10. 在结果页通过 `← 1/3 →` 切换多套结果。
11. 点击 Wardrobe，查看静态 2 列款式列表。
12. 切到后台。
13. 在 List page 查看款式列表。
14. 点击某个款式进入 Detail page。
15. 设计师提交审核，或商家运营审核通过。
