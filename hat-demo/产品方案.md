# 帽子 Demo 产品与设计方案

## 一、产品方案

### 1. 目标定位

这个 Demo 面向售前演示，用来展示 `yescaps.shop` 作为帽子行业 ToB 定制批发交易平台的完整能力。

它不是普通 C 端商城，也不是品牌展示官网。核心叙事是：

> 给帽子品牌、批发商、工厂客户使用的一站式帽子定制、批发下单、在线支付 / 凭证支付和大货履约管理平台。

销售演示时需要让客户快速看到三件事：

1. 平台能承接帽子定制批发交易，而不只是展示商品。
2. 定制器是核心亮点，可以把帽型、颜色、材质、Logo、工艺、数量和价格串起来。
3. 后台能支撑数据看板、订单、商品、定制配置和评价管理。

### 2. 第一版边界

第一版先做一个完整、可信、可点击的售前 Demo。

必须完成：

- 轻入口页
- 商城端多视图
- 热销款式
- 商品列表与帽型筛选
- ToB 商品详情
- 可交互帽子定制器
- 采购单
- 批发订单确认
- 在线支付 / 凭证支付
- 买家中心：账号、地址、我的订单
- 客服入口占位
- 后台数据看板
- 后台订单管理
- 后台商品管理
- 后台定制配置
- 后台评价管理

暂不做：

- 真实客服聊天
- 案例 / 社区 / 买家秀
- 真实登录
- 真实文件上传
- 真实支付
- 真实 3D 渲染
- 完整 ERP 流程

### 3. 文件结构

Demo 采用静态 HTML，不引入复杂构建流程。页面按角色边界拆分，而不是按每个商城页面拆分。

```text
hat-demo/
  index.html        # 轻入口：商城端 / 管理后台
  shop.html         # 商城端，内部多视图切换
  admin.html        # 管理后台，内部多视图切换
  shared.css        # 通用视觉样式
  data.js           # 商品、帽型、材质、工艺、价格、订单模拟数据
  shop.js           # 商城端交互
  admin.js          # 后台端交互
```

现有 `hat-screen.*` 文件属于早期占位框架。正式实现时建议替换为上面的结构，演示入口切换到 `hat-demo/index.html`。

### 4. 信息架构

#### 入口页

`index.html` 只作为轻量 Demo 控制台，不做营销官网。

入口：

- 商城端：进入选款、定制、批发下单链路。
- 管理后台：进入运营、销售和生产协作视角。

#### 商城端

`shop.html` 内部通过 hash 或 JS 状态切换多个视图：

```text
shop.html#/home
shop.html#/popular
shop.html#/products
shop.html#/product
shop.html#/customizer
shop.html#/cart
shop.html#/order
shop.html#/account
```

商城端优先级：

1. 帽子定制器
2. 批发下单链路
3. ToB 商品详情和阶梯价
4. 采购单
5. 商品目录和帽型筛选
6. 买家中心：账号、地址、我的订单
7. 热销款式、收藏点赞、轻评价

#### 管理后台

`admin.html` 内部通过 hash 或 JS 状态切换多个视图：

```text
admin.html#/dashboard
admin.html#/orders
admin.html#/products
admin.html#/assets
admin.html#/reviews
```

后台优先级：

1. 数据看板
2. 订单管理
3. 商品管理
4. 定制配置
5. 评价管理

### 5. 商城端核心体验

#### 首页

首页不做泛泛的 C 端商城氛围，第一屏直接突出定制批发交易。

核心模块：

- 开始定制入口
- 热销款式
- 批发阶梯价示例
- 工艺能力展示
- 客服入口占位

主 CTA：

- 开始定制
- 查看热销款式
- 联系客服获取人工报价

客服入口只做静态展示，不实现真实客服。

#### 热销款式

热销款式用于替代案例、社区和买家秀，承担采购决策辅助。

展示：

- 热销排名
- 帽型名称
- 起始阶梯价
- 采购评价摘要
- 收藏入口
- 开始定制

热销页需要保留筛选和排序控件，让页面像真实采购目录：

- 帽型筛选
- 团购场景筛选
- MOQ 筛选
- 工艺筛选
- 排序：本月销量 / 采购评价 / 最新上架

第一版筛选和排序只做可操作样式，不需要真实过滤。评价弱展示即可，不作为主功能。商品图片上不放评分角标，避免和信息区重复。

#### 商品列表

商品列表是采购目录，不做 C 端瀑布流。

筛选维度：

- 帽型：棒球帽、卡车帽、渔夫帽、冷帽、五片帽、遮阳帽
- 帽檐：平檐、弯檐
- 后扣：金属扣、魔术贴、塑料扣、弹力封闭
- 帽身结构：硬挺、软顶
- 后片：全布、网布
- 材质：棉斜纹、水洗棉、羊毛混纺、灯芯绒、尼龙、防晒面料
- 工艺：平面刺绣、立体刺绣、胶印、织标、皮标、金属标
- MOQ：50 件、100 件、300 件、1000 件
- 交期：快速排产、标准大货

商品卡片展示：

- 帽型图片
- 帽型名称
- 起始价格
- 起订量
- 大货周期
- 1 个弱标签，例如热销 / 企业团购 / 低 MOQ
- 开始定制
- 加入收藏

商品卡片不做小型商品详情。采购评价、完整标签、阶梯价和工艺信息放到商品详情页，避免列表卡片过重。

帽檐、后扣、结构、后片这些归类为帽型属性，不单独放到复杂定制步骤里。

#### 商品详情

商品详情必须体现 ToB 批发场景。

上方采用传统商品详情结构，不做大首屏：

- 左侧：商品主图和缩略图
- 右侧：商品核心信息、阶梯价摘要、工艺和操作按钮

右侧核心信息：

- 阶梯价：50-99 / 100-299 / 300-999 / 1000+
- 大货周期
- 帽型属性
- 可用工艺
- 采购评价摘要

核心操作：

- 开始定制
- 加入收藏
- 联系客服

不定制不能直接加入采购单，因此商品详情不提供 `加入采购单`。采购单入口只出现在定制器数量报价之后。

商品详情下方采用 Tab 结构，避免核心信息和详细内容重复：

- 产品介绍：产品说明、产品特性、可定制部位
- 定制说明：定制流程卡片、起订和报价规则、定制能力点
- 采购评价：评分概览、评分分布、采购反馈关键词和评价列表

#### 帽子定制器

定制器是 Demo 的核心亮点。

第一版需要做到可真实交互：

1. 帽型规格
2. 细节定制
3. 数量报价
4. 订单确认

步骤说明：

- 帽型规格：基于当前商品选择核心结构参数，不展示其它商品。
- 细节定制：用 2D 图片模拟 3D 定制画布，预览区管理细节方案，参数区只编辑当前方案的面料、DIY 配色和 Logo。
- 数量报价：按细节方案和固定尺码列表填写数量，展示总数量、阶梯价和预计总价。
- 订单确认：输入公司、联系人、地址和支付方式，提交订单。

配置项：

- 帽身结构：硬挺、软顶
- 帽身高度：标准、加深
- 帽檐：弯檐、平檐
- 后扣：金属扣、魔术贴、塑料扣、弹力封闭
- 细节方案：方案 1 / 方案 2 / 新增方案，放在预览区，用缩略图列表切换
- 面料：帽身面料、帽檐面料、后片面料
- DIY 配色：帽身颜色、帽檐颜色、后片颜色、纽扣 / 气眼颜色，预设色只作为快捷入口
- Logo：支持多个 Logo；每个 Logo 可选择上传图片或文字 Logo，文字 Logo 支持输入文字和字体
- Logo 工艺：每个 Logo 独立选择平面刺绣、立体刺绣、胶印、织标等工艺

细节定制页结构：

- 左侧：方案缩略列表 + 当前方案大图预览
- 右侧：参数编辑区，使用 Tab 切换面料、配色、Logo / 工艺
- 方案缩略卡必须包含图片、方案摘要、配色色块和 Logo 数量，避免只有方案编号导致用户无法识别
- 参数 Tab 的当前选中态需要明显，使用深色实底；普通参数选项保持轻量选中态
- 抽屉只作为后续上传 Logo、自定义颜色等二级编辑入口，不作为主配置流程

报价联动：

- 基础帽型单价
- 数量阶梯折扣
- 材质升级费用
- Logo 工艺费用
- 细节方案数量
- 生产准备费
- 加急费

报价展示：

- 当前总数量
- 当前阶梯
- 单件估价
- Logo 工艺加价
- 生产准备费
- 预计总价
- 预计大货周期

数量报价页提供两个路径：

- 加入采购单：保存当前定制方案，继续选择其它帽型或其它定制方案。
- 立即下单：当前定制方案直接进入订单确认。

采购单类似购物车，但面向 B 端批发场景，页面命名建议使用 `采购单`。

#### 采购单

采购单用于承接多个定制方案，提交订单前可以统一确认。

展示：

- 定制方案列表
- 每个方案的帽型、颜色、Logo 位置、工艺
- 多色多规格数量表
- 单方案小计
- 总数量
- 总金额
- 继续选款
- 进入订单确认

采购单和我的订单的区别：

- 采购单：订单提交前，用于整理多个定制方案。
- 我的订单：订单提交后，用于查看支付状态、上传凭证和查看生产状态。

#### 批发订单确认

下单链路要特别体现批发场景。

帽子存在多色和规格，但不需要像服装一样做复杂尺码表。第一版支持：

- 细节方案拆单
- 固定尺码列表
- 总数量汇总
- 阶梯价按总数量计算
- 单色 MOQ 提示

数量报价示例：

| 细节方案 | 均码 | S-M | L-XL | 儿童 | 小计 |
|---|---:|---:|---:|---:|---:|
| 方案 1 | 120 | 0 | 40 | 0 | 160 |
| 方案 2 | 80 | 0 | 20 | 0 | 100 |
| 方案 3 | 60 | 0 | 0 | 0 | 60 |

规格建议：

- 均码
- S-M
- L-XL
- 儿童

价格规则：

- 总 MOQ：例如 100 件起
- 单色 MOQ：例如每色 50 件起
- 阶梯价按总数量计算
- 页面显示方案拆分、尺码数量和总数量

#### 支付方式

订单确认时选择支付方式：

- 在线支付
- 凭证支付

凭证支付用于银行转账、对公付款。凭证不在订单确认页上传，而是在下单后进入买家中心的我的订单中提交。

订单页展示：

- 订单明细
- 定制配置
- 多色多规格数量表
- 阶梯价
- 工艺费用
- 生产准备费
- 预估总价
- 交期
- 公司名称
- 联系人
- 邮箱 / 电话
- 收货地址
- 支付方式

核心操作：

- 确认订单
- 在线支付

凭证支付订单提交后进入 `待支付` 状态，用户可在我的订单中上传支付凭证。

#### 买家中心

买家中心用于体现 B 端客户自己的基础后台，但第一版保持轻量。

模块：

- 账号管理
- 地址管理
- 我的订单

账号管理展示：

- 公司名称
- 联系人
- 邮箱 / 电话

地址管理展示：

- 默认收货地址
- 新增 / 编辑地址占位

我的订单展示：

- 订单编号
- 定制帽型
- 总数量
- 支付方式
- 支付状态
- 订单状态
- 大货周期

凭证支付订单在我的订单中提供 `上传支付凭证` 入口。Demo 可做上传占位，不做真实文件上传。

#### 订单状态

Demo 里需要体现设计稿确认作为状态节点，但不展开成页面功能。

状态链：

```text
待支付 → 支付审核中 → 待确认设计稿 → 生产中 → 已发货
```

在线支付可以跳过 `支付审核中`：

```text
待支付 → 待确认设计稿 → 生产中 → 已发货
```

`待确认设计稿` 作为销售讲解点保留。真实实施时可根据客户业务决定是否接入生产确认稿和客户确认流程。

### 6. 后台范围

后台是售前证明平台完整性的辅助视角，不做完整 ERP。

#### 数据看板

数据看板作为独立菜单保留，使用静态图表展示电商核心数据，不做筛选和额外操作。

展示：

- 今日订单数
- 今日成交额
- 待支付订单
- 支付审核中订单
- 生产中订单
- 本月成交额
- 近 7 日成交趋势
- 订单状态分布
- 热销商品排行
- 采购转化漏斗

#### 订单管理

展示：

- 订单列表页
- 订单详情页
- 客户公司
- 商品 / 帽型
- 总数量
- 多色多规格摘要
- 支付方式
- 支付状态
- 订单状态
- 大货周期
- 生产资料下载
- 凭证支付订单的凭证审核入口

订单列表和订单详情分开，不在列表页常驻右侧详情。点击订单行进入订单详情页，详情页提供返回订单列表入口。

状态建议：

- 待支付
- 支付审核中
- 待确认设计稿
- 生产中
- 已发货

凭证审核基于订单，不单独作为后台菜单。凭证支付且状态为 `支付审核中` 的订单，在订单详情里显示凭证图占位和通过 / 驳回操作。

#### 商品管理

展示：

- 商品图
- 商品名称
- 商品基础信息
- MOQ
- 单色 MOQ
- 基础价格
- 阶梯价
- 可定制规格
- 可用面料
- 可用工艺
- 上下架状态
- 热销排序

商品管理仍然是商品维度，不改成帽型库。可定制规格跟随商品配置，不同商品可启用不同规格项，例如帽身结构、帽身高度、帽檐、后扣、后片等。

商品管理需要体现增删查改能力。Demo 不实现真实 CRUD，但页面需要提供搜索、筛选、新建商品、批量导入，以及每行查看 / 编辑 / 下架操作。

#### 定制配置

展示：

- 面料库
- 工艺库
- 字体库
- 费用配置

定制配置使用 Tab + 列表结构，不使用卡片宫格。颜色不作为后台固定配置，前台由用户在定制器中 DIY 配色。

Logo 位置模板不作为后台主配置。前台按 3D / 画布定位逻辑讲，位置、缩放和旋转默认在画布中完成。

#### 评价管理

展示：

- 商品
- 客户
- 评分
- 商品评价列表
- 评价精选 / 隐藏

评价管理保持轻量，不做完整社区审核。

### 7. 销售演示路径

推荐销售演示顺序：

1. 打开入口页，说明这是帽子行业 ToB 定制批发交易平台。
2. 进入商城端，展示热销款式和批发属性。
3. 进入商品详情，强调 MOQ、单色 MOQ、阶梯价、帽型属性、工艺和交期。
4. 进入定制器，现场切换帽型、颜色、材质、Logo 位置和工艺。
5. 调整数量，展示报价联动。
6. 进入订单确认，展示多色多规格拆单和总数量阶梯价。
7. 展示在线支付 / 凭证支付。
8. 切到后台，展示数据看板、订单管理、凭证审核和状态流转。
9. 展示商品管理和定制配置，说明平台可持续配置商品、规格、颜色、材质和工艺。

## 二、设计方案

### 1. 设计原则

整体视觉应该偏专业、干净、有制造业和品牌定制感。

关键词：

- B2B 独立站
- 批发采购
- 定制工具
- 清晰报价
- 克制后台

避免：

- 过度潮牌化
- 纯 C 端零售感
- 大面积装饰性渐变
- 过多营销落地页式卡片
- 社区信息流风格

### 2. 视觉基调

建议使用浅色、克制、专业的系统视觉。

基础风格：

- 背景：白色 / 极浅灰
- 主文字：近黑色
- 次级文字：中性灰
- 线条：浅灰细线
- 强调色：深绿色或深蓝，少量使用
- 状态色：支付、审核、生产等状态使用低饱和标签

卡片圆角控制在 6-8px，不做过大的圆角。

### 3. 商城端结构

商城端使用顶部导航，不用后台式左侧菜单。

顶部导航：

- yescaps.shop
- 新品&热销
- 棒球帽
- 渔夫帽
- 遮阳帽
- 采购单
- 我的订单
- 收藏
- 账号

定制器不作为独立导航入口，必须从商品卡片或商品详情进入。客服入口在商品详情等业务位置出现，不做右下角悬浮。

#### 首页设计

首页第一屏直接承接交易。

建议结构：

- 左侧：开始定制入口和一句平台定位
- 右侧：热销款式榜 / 批发阶梯价小表
- 下方：热销款式、工艺能力、采购评价摘要

不做大营销 hero，不使用纯品牌故事页结构。

#### 商品列表设计

商品列表像采购目录。

布局：

- 左侧筛选栏
- 右侧 3-4 列商品网格

商品卡片：

- 帽子图片
- 帽型名称
- MOQ
- 起始阶梯价
- 可用工艺标签
- 评分 / 评价数
- 收藏按钮
- 开始定制按钮

点赞可以弱化为小图标，不作为主动作。

#### 商品详情设计

布局：

- 上方左侧：商品主图 / 缩略图
- 上方右侧：核心信息 / 阶梯价摘要 / 操作按钮
- 下方：详情 Tab

上方核心信息包含：

- 商品中英文名
- 帽型属性
- 阶梯价摘要
- 可用工艺
- 大货周期
- 采购评价摘要
- 开始定制
- 加入收藏
- 联系客服

详情 Tab：

- 产品介绍：产品说明、产品特性、可定制部位
- 定制说明：定制流程卡片、起订和报价规则、定制能力点
- 采购评价：评分概览、评分分布、采购反馈关键词和评价列表

上方和下方不重复同一组信息。MOQ 和单色 MOQ 放在 `定制说明`，上方只展示阶梯价摘要和大货周期。下方内容采用长页面内容流，不做卡片堆叠；通过标题、分隔线、段落、步骤流和评价列表形成真实商详质感。

#### 定制器设计

定制器采用三栏工具布局。

结构：

- 左侧：步骤和配置项
- 中间：帽子大预览
- 右侧：报价和订单摘要

步骤：

1. 帽型规格
2. 细节定制
3. 数量报价
4. 订单确认

右侧报价始终可见：

- 数量
- 当前阶梯
- 单价
- 工艺加价
- 生产准备费
- 预计总价
- 大货周期
- 加入采购单 / 立即下单

细节定制区按 3D 定制器逻辑设计：位置、缩放和旋转默认在画布中完成，右侧表单只管理当前方案的面料、DIY 配色和 Logo 元素本身。第一版用 2D 图片模拟，不承诺真实 3D。

#### 采购单设计

采购单页面类似购物车，但视觉和命名保持 B 端采购语境。

结构：

- 左侧：定制方案列表
- 右侧：总数量、总金额、进入订单确认

定制方案卡片展示：

- 帽型缩略图
- 定制摘要：颜色、材质、Logo 位置、工艺
- 多色多规格数量表
- 单方案小计
- 编辑配置
- 移除

核心操作：

- 继续选款
- 进入订单确认

#### 订单确认设计

页面名称建议用 `订单确认`，不要做普通零售 checkout 感。

结构：

- 左侧：订单明细、定制配置、多色多规格数量表
- 右侧：价格汇总和支付方式

支付方式：

- 在线支付
- 凭证支付

凭证支付只选择支付方式，不在订单确认页上传凭证。

提交后展示：

- 订单编号
- 支付方式
- 当前状态
- 预计大货周期

凭证支付订单提示用户到我的订单上传支付凭证。

#### 买家中心设计

买家中心不做完整会员系统，只体现 B 端客户下单后的基础自助能力。

顶部可从账号入口进入，页面内使用简单 Tab：

- 账号信息
- 地址管理
- 我的订单

账号信息：

- 公司名称
- 联系人
- 邮箱 / 电话

地址管理：

- 默认收货地址
- 新增 / 编辑地址按钮占位

我的订单：

- 订单编号
- 帽型 / 定制摘要
- 总数量
- 支付方式
- 支付状态
- 订单状态
- 上传支付凭证入口

凭证支付订单在 `我的订单` 中上传凭证；订单确认页只选择支付方式。

### 4. 后台设计

后台使用克制工作台风格，与商城端区分。

布局：

- 左侧菜单
- 顶部当前模块标题
- 主内容区表格 / 面板
- 列表页和详情页分离

左侧菜单：

- 数据看板
- 订单管理
- 商品管理
- 定制配置
- 评价管理

#### 数据看板设计

数据看板使用静态图表，不做筛选和交互。

页面模块：

- 顶部指标：今日订单、今日成交额、待支付、支付审核中、生产中、本月成交额
- 近 7 日成交趋势：柱状图
- 订单状态分布：横向条形图
- 热销商品排行：横向条形图
- 采购转化漏斗：进度条式漏斗

#### 订单管理设计

订单列表用高信息密度表格。

列表页顶部提供样子货搜索筛选，不实现实际过滤：

- 搜索订单编号 / 客户公司
- 支付方式
- 订单状态
- 下单时间
- 导出订单

表格字段：

- 订单编号
- 客户公司
- 商品
- 金额
- 支付方式
- 支付状态
- 订单状态

点击订单行进入订单详情页：

- 订单编号
- 客户公司
- 商品
- 总数量
- 订单金额
- 支付方式
- 支付状态
- 当前状态
- 定制方案摘要
- 凭证支付订单的凭证审核区
- 生产资料下载按钮

凭证审核合并到订单管理，不单独做菜单。

#### 商品管理设计

商品管理以商品维度维护前台可售商品，不改成帽型库。

列表页顶部提供：

- 搜索商品名称
- 商品类型筛选
- 状态筛选
- 批量导入
- 新建商品

字段：

- 商品图
- 商品名称
- 品类
- MOQ
- 起始价
- 可定制项数量
- 状态
- 操作：查看 / 编辑 / 下架

商品列表只展示判断和维护所需的核心字段。完整阶梯价、规格明细、面料和工艺放到查看 / 编辑入口中，不在列表中展开，避免表格过宽。

不同商品可启用不同可定制规格，不要求每个帽子都使用同一套规格。

#### 定制配置设计

定制配置使用 Tab + 列表展示：

- 面料库
- 工艺库
- 字体库
- 费用配置

每个 Tab 顶部提供：

- 搜索名称
- 状态筛选
- 新增配置

Logo 位置模板不作为主配置项，Logo 位置、缩放、旋转按定制画布能力讲。

#### 评价管理设计

保持轻量。

评价运营：

- 商品
- 客户
- 商品评价列表
- 评分
- 评价内容
- 精选 / 隐藏

评价列表顶部提供搜索商品 / 客户、评分筛选、状态筛选和精选评价按钮。Demo 不实现实际过滤。

### 5. 组件规范

按钮：

- 主按钮用于开始定制、确认订单、通过审核
- 次按钮用于加入采购单、联系客服、下载资料
- 图标按钮用于收藏、点赞、查看

表格：

- 后台表格行高紧凑
- 状态使用低饱和标签
- 金额和数量右对齐

价格：

- 阶梯价用表格展示
- 总价摘要放固定面板
- 批发数量变化时实时联动

表单：

- 数量输入使用表格或 stepper
- 支付方式使用 segmented control
- 订单确认页不放说明型流程文案，只保留支付方式选择；凭证上传入口在我的订单体现
- 多色多规格用表格，不用散乱卡片

操作按钮：

- 报价摘要中的 `加入采购单` 和 `立即下单` 横向排列
- `立即下单` 作为主按钮，`加入采购单` 作为次按钮
- 按钮区和报价明细之间保留间距，避免贴在摘要表格下方
