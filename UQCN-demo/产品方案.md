# UQCN Demo 产品方案

## 目标定位

UQCN Demo 是一个面向售前演示的多角色 Demo。

它不是单功能 AI Hub，也不是普通 CMS，而是：

> 基于款式 CMS 的 AI 商品内容生产平台。

核心逻辑：

```text
款式库
  → 选择主商品
  → 放入任务篮
  → 选择参照商品 / 材质 / 搭配单品
  → 创建 AI 生成任务
  → 结果进入审核
  → 审核通过后导出素材包
```

第一版重点展示三个入口：

1. 运营端 AI 工具
2. B 端团定设计工具
3. AI 运营管理后台

## 总体结构

```text
UQCN-demo/
  index.html        # 售前入口 / 三角色入口
  styles.css        # 通用视觉样式
  app.js            # 静态交互和页面状态
  产品方案.md       # 当前方案文档
```

后续如果内容变复杂，可以再拆分为：

```text
UQCN-demo/
  index.html
  operator.html     # 运营端 AI 工具
  designer.html     # B 端团定设计工具
  admin.html        # AI 运营管理后台
  shared.css
  data.js
```

第一版可以先保留单 HTML 多视图方式，避免过早拆得太碎。

## 一句话方案

UQCN Demo 应该做成：

> 以款式 CMS 为底座，用任务篮解决批量和参照物选择，用审核池保证 AI 结果可控，最终导出商品素材包。B 端团定设计作为独立亮点入口展示。

## 入口设计

入口页不是营销官网，而是售前演示控制台。

三个主入口：

```text
运营端 AI 工具
  商品内容生产、任务篮、审核、素材包导出

B 端团定设计工具
  衣服 + Logo 的选项式生成和 2D 自由编辑

AI 运营管理后台
  审核流、Prompt、权限、基础能力配置
```

## 1. 运营端 AI 工具

### 定位

运营端 AI 工具是主线。

它不应该做成多个孤立按钮：

```text
生成尺码图
生成材质图
生成对比图
生成穿搭图
生成模特图
```

而应该以“款式”为中心组织：

```text
款式库
  → 款式详情
  → AI 生成面板
  → 生成任务
  → 审核池
  → 素材包
```

这样客户看到的是一个能落地的业务系统，而不是几个 AI 小工具。

### 页面结构

```text
运营端 AI 工具
  - 款式库
  - 任务篮
  - AI 生成任务
  - 审核池
  - 素材包导出
```

### 款式库

款式库是运营端的基础页面。

展示字段：

```text
商品图
款号
商品名称
品类
颜色
材质
已生成素材数量
待审核数量
最近任务
操作
```

核心操作：

```text
加入主商品篮
查看款式详情
创建单款生成任务
批量导入商品
```

### 款式详情

款式详情用于展示单个款式的完整 AI 内容生产能力。

建议模块：

```text
商品基础信息
商品图片 / 原始素材
AI 生成面板
生成结果墙
审核记录
素材包记录
```

AI 生成面板包含：

```text
商品详情图扩展
指定商品成套穿搭
指定模特图
```

## 运营端核心 AI 能力

### 商品详情图扩展

用于生成商品详情页中需要补充说明的图。

包括：

```text
商品尺码对比图
材质展示图
商品对比图
商品穿搭细节图
```

说明：

- 尺码对比图主要依赖当前款式，适合自动批量。
- 材质展示图需要材质参考或纹理参考，适合半自动批量。
- 商品对比图需要对比商品，适合任务篮方式。
- 穿搭细节图需要搭配参照物，适合任务篮方式。

### 指定商品成套穿搭

用于基于某个商品生成搭配图。

可配置项：

```text
主商品
商品颜色
搭配参照商品
场景：白底 / 棚拍 / 门店 / 生活方式场景
图片比例
清晰度
```

它需要参照商品，不适合无脑批量生成。

### 指定模特图

用于生成指定商品的模特展示图。

可配置项：

```text
主商品
商品颜色
模特性别
模特风格
场景
图片比例
清晰度
```

指定模特图主要依赖当前款式和统一参数，适合自动批量。

## 任务篮机制

任务篮是本方案的关键。

它解决的问题是：

> 穿搭、材质展示、商品对比都需要参照物，不能像尺码图一样直接批量生成。

任务篮分为两类：

```text
主商品篮
  放入需要生成内容的商品

参照篮
  放入搭配商品、对比商品、材质参考图、场景参考图
```

创建任务时，系统基于两个篮子做组合。

### 穿搭任务示例

```text
主商品篮：
  吊带
  衬衫
  外套

参照篮：
  裤子
  半裙
  鞋包
  内搭
```

系统生成组合：

```text
A001 吊带 + B021 阔腿裤 + 白底棚拍
A002 衬衫 + B018 半裙 + 通勤场景
A003 外套 + B033 内搭 + 门店场景
```

### 商品对比任务示例

```text
主商品篮：
  本季重点款

参照篮：
  同类款
  历史款
  竞品款
```

生成内容：

```text
版型对比
颜色对比
细节对比
适用场景对比
```

### 材质展示任务示例

```text
主商品篮：
  目标商品

参照篮：
  面料图
  纹理图
  光泽参考图
```

生成内容：

```text
材质近景
纹理细节
光泽表现
垂感说明
```

## 批量生成策略

批量生成分为两类。

### 自动批量

适合依赖当前款式、参数可统一配置的内容。

包括：

```text
尺码对比图
指定模特图
基础白底图
统一比例 / 清晰度导出
```

流程：

```text
选择多个款式
  → 选择自动批量模板
  → 设置统一参数
  → 创建生成任务
  → 结果进入审核
```

### 半自动批量

适合需要参照物的内容。

包括：

```text
穿搭图
材质展示图
商品对比图
```

流程：

```text
选择主商品
  → 选择参照物
  → 系统生成组合预览
  → 人工调整组合
  → 提交生成
  → 结果进入审核
```

### 组合预览

半自动批量必须有组合预览，否则批量会失控。

组合预览展示：

```text
主商品
参照商品 / 参照素材
任务类型
场景
生成状态
可替换参照物
```

用户可以在提交前调整组合。

## 审核规则

所有 AI 生成结果都必须进入审核。

这是 Demo 的关键原则：

> AI 可以批量生产，但不能绕过审核直接交付。

状态建议：

```text
生成中
待审核
已通过
已驳回
需微调
已导出
```

审核动作：

```text
通过
驳回
重新生成
局部微调
查看 Prompt
加入素材包
```

审核页应该支持按以下维度筛选：

```text
任务
款式
生成类型
状态
创建人
审核人
时间
```

## 素材包导出

第一版主出口只考虑“导出素材包”。

暂不把“发布到商品详情页 / 内容系统”作为第一版主链路。

素材包内容：

```text
图片文件
商品基础信息
生成类型
图片比例
清晰度
Prompt 摘要
审核状态
优化文案 / 图片说明
```

导出方式：

```text
按款式导出
按任务导出
按审核通过结果导出
批量导出 ZIP
导出 CSV / JSON 商品信息
```

售前演示中可以展示一个导出面板：

```text
素材包名称：春夏新品详情图素材包
包含款式：24 个
包含图片：186 张
审核通过：168 张
需微调：12 张
已驳回：6 张
导出格式：ZIP + CSV
```

## 2. B 端团定设计工具

### 定位

B 端设计工具是独立链路，不并入 AI 运营后台。

它服务团定场景：

```text
选择衣服
  → 上传 Logo
  → 调整 Logo 位置和大小
  → 生成团定效果图
```

### 方式一：选项式生成

适合低门槛快速生成。

流程：

```text
选择衣服
  → 上传 Logo
  → 选择 Logo 尺寸
  → 选择内置 Logo 位置
  → 生成效果图
```

内置位置示例：

```text
左胸
右胸
胸前居中
后背居中
下摆
```

Logo 尺寸示例：

```text
小
中
大
自定义
```

### 方式二：2D 自由编辑

适合专业可控。

流程：

```text
选择衣服
  → 上传 Logo
  → 进入 2D 编辑画布
  → 拖动 Logo 位置
  → 调整 Logo 大小
  → 确认生成效果图
```

2D 编辑基础能力：

```text
拖拽
缩放
旋转
删除
重置
预览
确认生成
```

第一版可以做静态交互，不需要真实图片合成。

## 3. AI 运营管理后台

### 定位

后台只服务运营端 AI 工具，不服务 B 端团定设计工具。

后台的目标是证明：

```text
AI 生成有权限、有审核、有 Prompt 管理、有基础能力配置。
```

### 后台模块

```text
数据看板
审核中心
账号与权限
审批流
Prompt 管理
基础能力配置
```

### 数据看板

展示：

```text
今日生成任务
待审核图片
通过率
驳回率
需微调数量
已导出素材包数量
热门生成类型
```

### 审核中心

展示：

```text
待审核
已通过
已驳回
需微调

```

操作：

```text
通过
驳回
局部微调

```

### 账号与权限

基础能力：

```text
分账号

```

角色示例：

```text
运营
审核员

```

## 关键产品判断

### 不做单功能 AI Hub

单功能 AI Hub 的问题：

```text
能力割裂
不像业务系统
难以解释审核、导出、权限、批量
客户容易理解成几个 AI 小工具
```

### 采用款式 CMS + 任务篮

优势：

```text
以款式为业务中心
天然承接批量生成
能解释参照物选择
能接审核和素材包导出
更像真实 ToB 平台
```

### 批量不是一个按钮

批量生成应该被解释为：

```text
自动批量
  + 半自动参照物配置
  + 组合预览
  + 审核治理
  + 素材包导出
```

这样更符合真实商品运营场景。

## 后续待确认

1. UQCN Demo 是否使用真实品牌名，还是保持中性系统名。
2. 第一版是否需要真实服装素材，还是先用占位图 / 静态样例图。
3. 运营端、B 端、后台是否拆成三个 HTML，还是先用一个 HTML 多视图。
4. 售前演示是否需要支持中英文切换。
5. 任务篮里的参照物是否只用商品，还是同时支持材质图、场景图、模特图。

## 运营端结构修订记录

### 系统感调整

运营端需要像真实业务系统，而不是售前说明页。

顶部结构：

```text
左侧：UQCN Content Studio / 商品内容生产工作台
右侧：搜索 / 通知 / 帮助 / 登录账号
  登录账号下拉提供系统切换：
    - 运营端 AI 工具
    - B 端团定设计
    - AI 运营后台
```

系统模块切换不要作为横向主导航暴露，应放在登录账号区域，降低 Demo 感。

顶部不要出现 `Demo`、`售前演示` 这类暴露演示属性的文案。

顶部高度控制在正式后台系统的 56-64px 左右，业务系统名称和业务菜单主要由侧边栏和页面标题承载。

### 运营端菜单调整

运营端一级菜单调整为：

```text
款式库
AI工具
任务列表
审核进度
```

不再把以下内容作为运营端一级菜单：

```text
任务篮
素材包
```

任务篮作为创建生成任务流程中的内部步骤出现，不直接暴露为一级模块。

素材包模块取消。已审核任务的结果在任务或审核进度中下载。

### 侧边导航与第二侧栏

当前阶段不启用固定第二侧栏。

原因：

```text
运营端当前一级模块数量有限
强行增加第二侧栏会显得空
双侧栏容易暴露 Demo 拼装感
客户第一眼更需要看到一个完整、可信的业务系统
```

当前采用“窄单侧栏 + 内容区筛选”的方式：

```text
左侧主导航：
  - 窄栏
  - icon 为主
  - 当前项高亮
  - hover 显示名称
  - 可预留展开态，展开后显示 icon + 名称

内容区：
  - 页面标题
  - 搜索
  - 筛选器
  - 视图切换
  - 批量操作
```

第二侧栏作为保留设计，不在当前第一版启用。

后续只有当某个模块内部分类足够丰富时才启用，例如：

```text
款式库：
  - 全部款式
  - 待补图
  - 生成中
  - 待审核
  - 已完成
  - 自定义文件夹 / 系列 / 季节

AI工具：
  - 商品图生成
  - 材质展示
  - 商品对比
  - 穿搭细节
  - 指定模特

任务列表：
  - 全部任务
  - 生成中
  - 待审核
  - 已完成
  - 异常任务
```

如果启用第二侧栏，它应该是“当前模块的局部分类”，不是系统切换入口。

系统切换仍然只放在右上角账号菜单中。

单款式内容主页可以启用局部第二侧栏。

这是第二侧栏当前最合理的使用场景，因为单款式内容主页存在稳定的局部分类：

```text
档案摘要
内容类型
颜色规格
```

布局建议：

```text
左侧主侧栏：系统导航
中间局部第二侧栏：当前款式内容目录
右侧主内容：图片内容管理
```

局部第二侧栏只服务当前款式，不承担系统切换，不在款式库列表页常驻。

图片内容区只保留与图片相关的操作：

```text
上传图片
AI 创建
选中后发起审核 / 批量删除
```

单款式内容主页不再把“AI创建”和“创建任务”并列展示。

对用户来说，AI创建本身就是发起生成，不需要暴露“创建任务”这个系统概念。

交互方式：

```text
点击 AI创建
  → 右侧弹层
  → 选择生成类型
  → 配置颜色 / 比例 / 参照物 / 数量
  → 开始生成
  → 任务进入任务列表和审核流程
```

任务列表只负责查看进度、结果和下载，不作为内容主页的主操作。

款式信息不要放在页面顶部形成重头部。

单款式内容主页顶部只做页面定位：

```text
返回款式库
不展示大标题
```

当前款式信息放在局部第二侧栏顶部的紧凑款式卡中。

款式卡片只放少量上下文：

```text
当前款式
款式名称
品类
卖点
简介
查看详情
```

款式卡片区域要小，不放商品图，不做完整资料展示。商品图作为“商品图”类型资产，放在右侧图片内容区。

点击“查看详情”后从右侧打开详情抽屉：

```text
款式详情
查看完整信息
编辑信息档案
保存 / 取消
```

这样不打断图片管理主流程，也避免顶部和第二栏重复展示款式信息。

### 顶部导航调整

进入具体系统后，不再保留全局顶部导航栏。

原因：

```text
顶部同时出现品牌、搜索、通知、帮助、账号，会很像售前 Demo 外壳
真实业务系统进入后，主导航应该由当前系统自己的侧边栏承载
账号、通知、系统切换更适合放在侧栏底部
```

当前系统内布局：

```text
左侧展开侧栏：
  - 顶部：当前系统名称
  - 中部：当前系统菜单
  - 底部：通知 / 设置 / 当前账号

右侧内容区：
  - 页面标题
  - 页面级操作
  - 搜索与筛选
  - 业务内容
```

侧栏与内容区需要有明显分界：

```text
侧栏固定白底
右侧使用明确分割线
内容区从分割线后开始
不使用悬浮白框式侧栏
```

### 日本客户视觉方向

整体风格参考日本企业级 SaaS / 零售运营系统：

```text
大面积白底
低饱和浅灰背景
细边框
轻选中态
少阴影
主色只用于关键操作和当前状态
字体层级克制
内容信息密度高于营销页
```

避免：

```text
大面积品牌色背景
夸张渐变
过大的卡片和按钮
说明性文案过多
看起来像三套 Demo 入口拼在一起
```

款式库、任务列表、审核进度都应该更像真实工作台，而不是展示页。

### 审核职责划分

运营端不执行审核操作。

运营端只查看任务审核进度：

```text
任务是否生成完成
审核进度到哪一步
通过 / 驳回 / 需微调数量
已审核任务是否可下载
```

真正的审核动作放在 AI 运营管理后台：

```text
通过
驳回
局部微调
重新生成
```

### 款式库与单款式内容主页

款式库是 CMS 主入口，支持双模式：

```text
大图模式
列表模式
```

优先展示大图模式。

款式库列表页的主操作是款式档案管理：

```text
新建款式档案
批量导入
```

视图切换使用图标控件，不作为主要按钮出现：

```text
大图模式 icon
列表模式 icon
```

列表页不直接放“创建任务”作为主操作。

创建任务需要下沉到单款式内容主页或批量任务流程中，因为任务通常依赖具体款式、图片资产、颜色和参照物。

款式卡片不展示款式审核状态。

审核属于内容素材，不属于款式档案本身。

卡片信息建议：

```text
款式名称
品类
素材概况
```

素材概况可以用轻量分段条呈现，不使用醒目的状态标签：

```text
总素材数
已审核数量
审核中数量
未审核数量
```

这样既能让运营看到内容完整度，又不会让卡片看起来像任务审核列表。

搜索和筛选属于列表控制区，不属于主按钮区：

```text
搜索款式名称 / 款号 / 品类
按品类筛选
按素材状态筛选
大图 / 列表视图切换
```

列表页和单款式内容主页要分开：

```text
款式库
  → 单款式内容主页
```

不要把款式列表和内容主页堆在同一个页面。

### 单款式内容主页

命名使用：

```text
单款式内容主页
```

不要叫“详情页”。详情页听起来像资料查看页，但这里是围绕单个款式做内容资产管理。

单款式内容主页的主角是内容资产，不是信息档案。

页面主目标：

```text
这个款式有哪些图
哪些颜色缺图
哪些图待审核
哪些图可下载
能否上传 / AI 创建 / 发起审核 / 删除 / 大图查看
```

### 图片资产管理

单款式内容主页的图片区域要支持：

```text
大图查看
删除图片
上传图片
AI 创建图片
发起审核
批量选择
批量删除
批量发起审核
```

图片资产按两层组织：

```text
一级：图片类型
  - 商品图
  - 尺码对比图
  - 材质展示图
  - 商品对比图
  - 穿搭细节图
  - 指定模特图

二级：颜色
  - 全部
  - 款式已有颜色
```

颜色是资产归属维度，不只是标签。

标签是辅助描述维度，例如：

```text
白底
棚拍
门店
正面
背面
近景
通勤
```

### 信息档案

信息档案需要能编辑，但它是次要能力。

单款式内容主页只展示信息档案摘要，例如：

```text
品类
颜色
材质
卖点
搭配建议
```

编辑信息档案通过按钮进入独立页面：

```text
单款式内容主页
  → 编辑信息档案
```

不要在单款式内容主页直接展开大表单，避免主次倒置。

页面状态建议：

```text
stylePage: "list" | "content" | "profileEdit"
styleViewMode: "grid" | "list"
```

### AI 工具菜单

运营端需要保留单点 AI 工具入口。

AI 工具不是任务列表，也不是跳转到某个任务。

它是能力入口，适合做成工具卡片：

```text
商品尺码对比图
材质展示图
商品对比图
穿搭细节图
指定模特图
```

卡片整张可点击，不单独放“使用工具”按钮。

点击工具卡后进入完整工具页面，不和款式内容主页共用右侧弹层。

从款式内容主页进入时，右侧弹层默认带当前款式；从 AI 工具菜单进入时，页面不预填具体目标，需要用户从款式库选择或上传图片。

关系：

```text
款式库 = 从商品资产出发
AI工具 = 从具体能力出发
生成任务 = 任务执行与进度
审核进度 = 任务审核状态查看与下载
```

### B 端团定设计工具展示方式

B 端团定设计工具是能力演示，不是运营系统模块。

因此不要套运营端左侧系统菜单。

页面结构：

```text
顶部：工具名称 + 选项式 / 2D 编辑切换
主体：衣服画布 + 参数面板
```

不展示运营账号、通知、系统侧栏，避免看起来像另一个后台模块。

## 最新界面调整记录

### 头部统一规则

系统页头部只承担位置感，不承载业务按钮。

一级页面头部只保留标题：

```text
款式库
AI工具
任务列表
审核进度
```

二级页面只保留返回：

```text
← 返回款式库
```

页面按钮下沉到当前页面的工具栏或内容区，例如款式库的新建、批量导入放在搜索筛选行；单款式内容主页的上传、AI创建放在图片内容区。

### 运营端菜单

运营端主菜单保留：

```text
款式库
AI工具
任务列表
审核进度
```

不展示数据看板，避免售前 demo 看起来像把所有模块堆到主导航。

### 任务列表

任务列表是查看型页面，不承担创建、审核或再次操作。

列表结构：

```text
任务列表

全部 / 生成中 / 已完成 / 失败
搜索

任务图集卡片
```

任务卡以小图集呈现生成结果范围，展示任务类型、任务名、编号、进度、款式数量、图片数量和来源。

任务状态只保留：

```text
生成中
已完成
失败
```

审核相关状态放在审核进度，不放在任务列表。

点击任务卡打开右侧详情抽屉，列表不展开操作。

详情抽屉展示：

```text
任务标题 / 编号 / 时间
当前状态 / 当前阶段 / 进度
生产图片图集
生成类型 / 款式数量 / 图片数量 / 创建来源 / 提交人
```

### 审核进度

审核进度和任务列表使用一致的图集卡结构，只切换状态语义：

```text
全部 / 审核中 / 已审核
```

审核列表只展示当前状态，不在列表里展开完整流程。

点击审核卡打开右侧详情抽屉：

```text
审核任务标题 / 编号 / 更新时间
当前审核状态 / 审核阶段 / 进度
审核图片图集
审核步骤
生成数 / 待审 / 通过 / 驳回
```

### 图片选择与预览

单款式内容主页的图片卡片不使用显眼红色选中态。

卡片结构：

```text
小方框 checkbox
图片
标题 / 状态
颜色与标签
```

卡片 hover 不再出现“大图 / 删除”按钮，避免每张卡都像操作面板。

交互规则：

```text
点 checkbox：批量选择
点图片或卡片：打开右侧图片预览抽屉
```

选中图片后不再插入新的批量操作条，避免内容被挤压。图片内容顶部工具栏原地切换：

```text
未选中：图片内容        上传图片 / AI创建
已选中：已选 N 张       发起审核 / 取消选择 / 删除
```

图片预览使用右侧抽屉，不使用居中弹窗。

抽屉结构：

```text
图片预览                                      关闭
款式名称 · 类型 · 颜色 · 状态

上一张按钮        大图预览        下一张按钮
                                      1 / N

标签 / 来源                         类型 / 颜色

                                  AI创建 / 删除
```

切换范围基于当前筛选结果，例如当前内容类型和颜色规格筛选后的图片列表。

### AI 创建入口

款式内容主页里的 AI 创建使用右侧弹层，在售前 demo 中不展示空表单，打开后直接带当前款式和默认参数。

AI 工具菜单里的单点工具使用完整页面，标题就是具体工具名，目标内容不预填；参数可给默认值，方便演示时快速生成。

统一结构：

```text
目标内容
生成类型
参数项
图片比例
清晰度
生成数量
生成说明
开始生成
```

入口差异：

```text
款式库入口：自动带入当前款式、颜色、SKU、主图，只在当前款式内切换 SKU。
AI工具入口：不默认带入具体目标，允许从全库选择或上传图片。
```

各工具默认有值，用户看到的是“可以调整”，不是“必须从 0 填写”。
